# Shluz

Shluz — центральный API-шлюз между пользовательскими приложениями и поставщиками нейросетей.

```text
Harness / сайт / Telegram
          ↓
        Shluz
          ↓
Venice / Nous / OpenRouter / собственные модели
```

Пользовательские приложения обращаются только к Shluz. Реальные ключи поставщиков хранятся на сервере и не попадают в Harness, браузер или Telegram.

## Что уже работает

- проверка состояния сервера: `GET /health`;
- список моделей в формате OpenAI API: `GET /v1/models`;
- чат в формате OpenAI API: `POST /v1/chat/completions`;
- безопасный тестовый провайдер `mock`, не расходующий деньги;
- реальный текстовый провайдер Venice;
- безопасная обработка ошибок ключа, баланса и лимитов Venice;
- закрытая браузерная панель `/admin`;
- отдельная визуальная страница Venice: `/admin/providers/venice`;
- интерактивная документация `/docs`;
- Docker-упаковка, автоматические тесты и сборка.

В панели Venice отображаются состояние подключения, баланс USD/DIEM, возможность расходования, тариф API, срок ключа, каталог моделей, цены, лимиты и доступная аналитика общего расхода.

Пользователи, индивидуальные тарифы, подписки, права и персональный расход появятся после подключения PostgreSQL/Supabase.

## Самый простой запуск через Docker

1. Установите Docker Desktop.
2. Скопируйте `.env.example` в файл `.env`.
3. Замените значения `CHANGE_ME` на длинные случайные значения.
4. Оставьте `SHLUZ_ACTIVE_PROVIDER=mock` для бесплатной проверки.
5. Запустите:

```bash
docker compose up --build
```

После запуска откройте:

- панель управления: <http://localhost:8000/admin>;
- страницу Venice: <http://localhost:8000/admin/providers/venice>;
- документацию API: <http://localhost:8000/docs>;
- состояние сервера: <http://localhost:8000/health>.

Для входа в `/admin` используйте `SHLUZ_ADMIN_USERNAME` и `SHLUZ_ADMIN_PASSWORD` из `.env`.

## Подключение Venice

Создайте API-ключ Venice и сохраните его только в локальном `.env` или в разделе Secrets выбранного хостинга:

```dotenv
SHLUZ_ACTIVE_PROVIDER=venice
SHLUZ_VENICE_API_KEY=ваш_ключ
```

Затем перезапустите сервис:

```bash
docker compose up -d --build
```

После этого `/admin/providers/venice` покажет доступные данные аккаунта. Полное значение ключа в интерфейсе не отображается.

Не отправляйте API-ключ в чат и не сохраняйте его в GitHub.

## Проверка API

Откройте <http://localhost:8000/docs>, нажмите **Authorize** и укажите токен из `SHLUZ_BOOTSTRAP_API_TOKEN`. После этого можно выполнять запросы кнопкой **Try it out**.

В режиме `mock` используется модель `mock-chat`: она возвращает тестовый ответ и не обращается к внешним сервисам.

В режиме `venice` список моделей загружается из Venice, а чат отправляет реальный платный запрос выбранной модели.

## Безопасность

- Никогда не коммитьте `.env`.
- Не встраивайте ключи поставщиков в пользовательское приложение.
- В production используйте HTTPS и серверное хранилище Secrets.
- До публичного запуска замените временную авторизацию полноценными пользовательскими токенами и лимитами.
- Храните отдельные ключи для тестовой и рабочей среды.
