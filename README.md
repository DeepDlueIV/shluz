# Shluz

Shluz — центральный API-шлюз между пользовательскими приложениями и поставщиками нейросетей.

```text
Harness / сайт / Telegram
          ↓
        Shluz
          ↓
Venice / Nous / OpenRouter / собственные модели
```

Пользовательские приложения обращаются только к Shluz. Реальные ключи поставщиков хранятся на сервере и не попадают в Harness, браузер или Telegram.

## Что уже работает

- `GET /health` — состояние сервера;
- `GET /v1/models` — список моделей в формате OpenAI API;
- `POST /v1/chat/completions` — текстовый чат в формате OpenAI API;
- бесплатный тестовый провайдер `mock`;
- реальный текстовый адаптер Venice;
- постоянная база пользователей, способов входа, тарифов, подписок, токенов и расхода;
- персональные API-токены для Harness, сайта, Telegram и других каналов;
- автоматическая привязка каждого успешного запроса к пользователю и каналу;
- визуальное создание пользователей, выдача и отзыв токенов;
- запись модели, токенов и себестоимости без сохранения текста сообщений;
- хранение только необратимых хэшей пользовательских токенов;
- миграции базы, Docker-упаковка и автоматические проверки.

## Визуальная панель

После запуска доступны:

- <http://localhost:8000/admin> — сводка;
- <http://localhost:8000/admin/users> — пользователи, роли, статусы, личные токены и расход;
- <http://localhost:8000/admin/plans> — тарифы и лимиты;
- <http://localhost:8000/admin/usage> — токены, себестоимость, модели, каналы и журнал;
- <http://localhost:8000/admin/providers/venice> — баланс, модели, цены и ограничения Venice;
- <http://localhost:8000/docs> — интерактивная документация API;
- <http://localhost:8000/health> — техническая проверка.

Для входа в `/admin` используются `SHLUZ_ADMIN_USERNAME` и `SHLUZ_ADMIN_PASSWORD` из `.env`.

## Самый простой запуск через Docker

1. Установите Docker Desktop.
2. Скопируйте `.env.example` в файл `.env`.
3. Замените значения `CHANGE_ME` на длинные случайные значения.
4. Оставьте `SHLUZ_ACTIVE_PROVIDER=mock` для бесплатной проверки.
5. Запустите:

```bash
docker compose up --build
```

При старте Shluz автоматически применяет миграции базы. Локальные данные сохраняются в именованном Docker-томе `shluz_data` и не исчезают при обычном перезапуске контейнера.

## База данных

По умолчанию используется переносимый локальный файл SQLite:

```dotenv
SHLUZ_DATABASE_URL=sqlite+pysqlite:///./data/shluz.db
```

Для сервера или Supabase достаточно заменить одну закрытую настройку:

```dotenv
SHLUZ_DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST:5432/postgres?sslmode=require
```

Строка подключения является секретом. Её нельзя сохранять в GitHub или передавать пользовательским приложениям.

## Подключение Venice

Без API-ключа Venice **не вызывается**. Код адаптера и тесты работают без настоящего ключа, потому что тесты используют искусственные ответы, а приложение по умолчанию остаётся в режиме `mock`.

Для реальных платных запросов сохраните ключ только в локальном `.env` или Secrets хостинга:

```dotenv
SHLUZ_ACTIVE_PROVIDER=venice
SHLUZ_VENICE_API_KEY=ваш_ключ
```

Затем перезапустите:

```bash
docker compose up -d --build
```

Полное значение ключа в интерфейсе не отображается.

## Персональные токены пользователей

Администратор создаёт аккаунт на странице `/admin/users`, затем выдаёт ему токен и выбирает канал: Harness, сайт, Telegram или другое API.

Полное значение токена показывается только один раз. В базе остаются:

- необратимый SHA-256-хэш;
- короткий безопасный префикс для распознавания;
- пользователь, название и канал;
- время создания и последнего использования;
- статус отзыва.

Токен передаётся клиентом в стандартном заголовке:

```text
Authorization: Bearer shluz_...
```

Отозванный токен и токен заблокированного пользователя перестают работать сразу. Общий `SHLUZ_BOOTSTRAP_API_TOKEN` пока сохранён только для локальной проверки и первоначальной настройки.

## Учёт расходов

Каждый успешный запрос относится либо к личному аккаунту и выбранному каналу, либо к техническому аккаунту `bootstrap` при использовании тестового общего токена.

В базе сохраняются:

- пользователь и источник;
- поставщик и модель;
- входные и выходные токены;
- себестоимость в USD и DIEM;
- безопасный ID запроса поставщика;
- статус и время.

Тексты сообщений и ответы модели в журнале расходов не сохраняются.

## Безопасность

- никогда не коммитьте `.env`;
- не встраивайте ключи поставщиков в пользовательское приложение;
- передавайте личный токен пользователю безопасным способом;
- при потере токена отзовите его и создайте новый;
- в production используйте HTTPS и серверное хранилище Secrets;
- храните отдельные ключи для тестовой и рабочей среды;
- до публичного запуска включите самостоятельную регистрацию, применение тарифов и блокировку перерасхода.
