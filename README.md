# Shluz

Shluz — центральный API-шлюз между пользовательскими приложениями и поставщиками нейросетей.

```text
Harness / сайт / Telegram
          ↓
        Shluz
          ↓
Venice / Nous / OpenRouter / собственные модели
```

Клиенты обращаются только к Shluz. Реальные ключи поставщиков хранятся на сервере и не попадают в Harness, браузер или Telegram.

## Что работает

- `GET /health` — состояние сервера;
- `GET /v1/models` — список моделей в формате OpenAI API;
- `POST /v1/chat/completions` — текстовый чат в формате OpenAI API;
- бесплатный тестовый провайдер `mock`;
- адаптер Venice для реальных запросов после добавления ключа;
- пользователи, способы входа, персональные API-токены и каналы;
- тарифы, подписки и месячные ограничения;
- контроль запросов, внутренних кредитов и себестоимости;
- расчётная выручка и валовая маржа;
- привязка каждого запроса к пользователю, тарифу, модели и каналу;
- визуальная административная панель;
- SQLite для локального теста и PostgreSQL/Supabase для сервера;
- Docker, миграции и автоматические проверки GitHub Actions.

Тексты пользовательских сообщений и ответы модели в журнале расходов не сохраняются.

## Визуальная панель

После запуска доступны:

- <http://localhost:8000/admin> — общая сводка;
- <http://localhost:8000/admin/users> — пользователи, тарифы, остатки и токены;
- <http://localhost:8000/admin/plans> — создание и изменение тарифов;
- <http://localhost:8000/admin/usage> — себестоимость, выручка, маржа и журнал;
- <http://localhost:8000/admin/providers/venice> — баланс, цены и лимиты Venice;
- <http://localhost:8000/docs> — интерактивная документация API;
- <http://localhost:8000/health> — техническая проверка.

Для входа в `/admin` используются `SHLUZ_ADMIN_USERNAME` и `SHLUZ_ADMIN_PASSWORD` из закрытых настроек.

## Запуск через Docker

1. Установите Docker Desktop.
2. Скопируйте `.env.example` в `.env`.
3. Замените все значения `CHANGE_ME`.
4. Оставьте `SHLUZ_ACTIVE_PROVIDER=mock` для бесплатной проверки.
5. Запустите:

```bash
docker compose up --build
```

Откройте <http://localhost:8000/admin>.

При старте контейнер автоматически применяет миграции. Локальная SQLite-база сохраняется в Docker-томе `shluz_data`.

GitHub Actions не только собирает образ, но и запускает контейнер, ждёт статус `healthy`, проверяет `/health` и выполняет тестовый запрос к `mock-chat`.

## База данных

Локальный режим:

```dotenv
SHLUZ_DATABASE_URL=sqlite+pysqlite:///./data/shluz.db
```

PostgreSQL или Supabase:

```dotenv
SHLUZ_DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST:5432/postgres?sslmode=require
```

Строка подключения является секретом. Её нельзя сохранять в GitHub или передавать пользовательским приложениям.

## Тарифы и ограничения

Для личного токена нужен активный тариф. Технический токен `bootstrap` оставлен только для первоначальной настройки и локального теста.

Тариф может ограничивать:

- число запросов за календарный месяц UTC;
- внутренние кредиты;
- фактическую себестоимость поставщиков;
- резерв кредитов перед каждым запросом.

Также тариф хранит справочную месячную цену и процент наценки.

Перед обращением к модели Shluz создаёт короткую резервацию. Это снижает риск одновременного перерасхода. После ответа резервация заменяется точными токенами и стоимостью. При ошибке модели резерв освобождается.

```text
расчётная выручка = себестоимость × (1 + наценка / 100)
кредиты = округление вверх(выручка / цена одного кредита)
маржа = выручка − себестоимость
```

Цена одного внутреннего кредита задаётся настройкой:

```dotenv
SHLUZ_CREDIT_UNIT_USD=0.001
```

Расчётная выручка пока не является подтверждённым банковским платежом. Платёжная система будет отдельным этапом.

## Персональные токены

Администратор создаёт пользователя на `/admin/users`, назначает тариф и выдаёт отдельный токен для Harness, сайта, Telegram или другого API.

Полное значение токена показывается один раз. В базе остаются только:

- необратимый SHA-256-хэш;
- короткий безопасный префикс;
- пользователь, канал и название;
- время создания и последнего использования;
- статус отзыва.

Клиент передаёт токен так:

```text
Authorization: Bearer shluz_...
```

Отозванный токен, заблокированный аккаунт, отключённый тариф и исчерпанный лимит прекращают доступ немедленно.

## Venice

Без настоящего API-ключа Venice не вызывается. Тесты используют искусственные ответы, а приложение по умолчанию работает через `mock`.

Для живых запросов ключ сохраняется только в `.env` или Secrets хостинга:

```dotenv
SHLUZ_ACTIVE_PROVIDER=venice
SHLUZ_VENICE_API_KEY=ваш_ключ
```

После изменения перезапустите контейнер:

```bash
docker compose up -d --build
```

## Безопасность

- не коммитьте `.env`;
- не встраивайте ключи поставщиков в клиент;
- используйте HTTPS в production;
- храните отдельные ключи для тестовой и рабочей среды;
- при потере пользовательского токена отзывайте его и создавайте новый;
- ограничивайте доступ к административной панели на уровне сети;
- не используйте общий bootstrap-токен для обычных пользователей.
