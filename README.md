# Shluz

Shluz — центральный API-шлюз между пользовательскими приложениями и поставщиками нейросетей.

```text
Harness / сайт / Telegram
          ↓
        Shluz
          ↓
Venice / Nous / OpenRouter / собственные модели
```

Клиенты обращаются только к Shluz. Ключи поставщиков, закупочные цены и правила маршрутизации остаются на сервере.

## Что уже работает

- OpenAI-совместимые `GET /v1/models` и `POST /v1/chat/completions`;
- бесплатный тестовый провайдер `mock`;
- адаптер Venice для реальных текстовых запросов после добавления вашего API-ключа;
- запись каждого запроса до вызова провайдера и фиксация токенов, стоимости и ошибок после ответа;
- переносимая база: SQLite локально либо PostgreSQL/Supabase на сервере;
- сущности пользователей, способов входа, балансов, тарифов, подписок, клиентских токенов и аудита;
- закрытая браузерная панель `/admin`;
- визуальные разделы пользователей, тарифов, расхода, клиентских ключей и Venice;
- интерактивная документация `/docs`;
- Docker-упаковка и автоматические проверки GitHub.

## Самый простой запуск через Docker

1. Установите Docker Desktop.
2. Скопируйте `.env.example` в `.env`.
3. Замените значения `CHANGE_ME` на длинные случайные значения.
4. Оставьте `SHLUZ_ACTIVE_PROVIDER=mock`, чтобы ничего не оплачивать.
5. Запустите:

```bash
docker compose up --build
```

Docker сохраняет локальную базу в отдельном томе, поэтому пользователи и история расхода не исчезают после обычного перезапуска контейнера.

После запуска откройте:

- <http://localhost:8000/admin> — главная панель;
- <http://localhost:8000/admin/users> — пользователи, роли, подписки и баланс;
- <http://localhost:8000/admin/plans> — тарифы, права и ограничения;
- <http://localhost:8000/admin/usage> — запросы, токены, стоимость и ошибки;
- <http://localhost:8000/admin/tokens> — безопасные метаданные клиентских ключей;
- <http://localhost:8000/admin/providers/venice> — данные поставщика Venice;
- <http://localhost:8000/docs> — ручная проверка API;
- <http://localhost:8000/health> — состояние сервера.

Для входа в `/admin` используйте `SHLUZ_ADMIN_USERNAME` и `SHLUZ_ADMIN_PASSWORD` из `.env`.

## База данных

По умолчанию используется SQLite:

```dotenv
SHLUZ_DATABASE_URL=sqlite+pysqlite:///./data/shluz.db
```

Это удобно для локальной разработки и небольшой закрытой проверки. Для рабочего сервера укажите строку PostgreSQL/Supabase:

```dotenv
SHLUZ_DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST:6543/postgres?sslmode=require
```

SQL-схема для Supabase находится в:

```text
supabase/migrations/20260929_01_accounting_foundation.sql
```

Она не применяется автоматически: сначала нужно выбрать активный Supabase-проект и отдельно подтвердить применение миграции.

## Подключение Venice

Код адаптера сам по себе не даёт доступ к Venice. Для живого подключения нужен ваш ключ:

```dotenv
SHLUZ_ACTIVE_PROVIDER=venice
SHLUZ_VENICE_API_KEY=ваш_ключ
```

После перезапуска запросы выбранной модели станут реальными и платными. Полное значение ключа никогда не показывается в браузерной панели и не должно попадать в GitHub.

## Проверка API

Откройте `/docs`, нажмите **Authorize** и укажите значение `SHLUZ_BOOTSTRAP_API_TOKEN`. В режиме `mock` используйте модель `mock-chat`: ответ будет тестовым, но событие расхода всё равно появится в `/admin/usage` с нулевой себестоимостью.

## Безопасность

- реальные `.env` и API-ключи не коммитятся;
- клиентам не выдаётся ключ Venice;
- пользовательские ключи Shluz хранятся только как хэш и безопасный префикс;
- если учёт недоступен до платного вызова, провайдер не вызывается;
- для production обязательны HTTPS, серверное хранилище Secrets и PostgreSQL/Supabase;
- прямой доступ браузерных клиентов к таблицам Supabase в начальной схеме закрыт.

Подробнее: [`docs/operations.md`](docs/operations.md).
