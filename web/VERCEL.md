# Просмотр NoClip и правила публикации

## Действующий проект

- Репозиторий: `DeepDlueIV/shluz`, ветка публикации: `main`.
- Vercel: `noclip-web`, ID `prj_IMSWjsl9RU0e8mV1RXv7QyLz0VJD`.
- Постоянный адрес: https://noclip-web.vercel.app
- Root Directory: `web`; Next.js; Node.js `24.x`; стандартные install/build/output.
- `NEXT_PUBLIC_GATEWAY_ENABLED=false`: просмотр интерфейса без реальных запросов к модели.
- Не задавать `NOCLIP_STATIC_EXPORT=1` и не указывать `out` как output.

## Подключение MCP

Чтение проекта/списка деплоев и изменение настроек проверены с известным projectId **без optional teamId и slug**. Подключение само выбирает доступный контекст. Пустой `list_teams` не означает, что проекты недоступны. Ранее переданный явный teamId приводил к 403; прежний общий диагноз «нет доступа к пространству» был слишком широким.

Некоторые низкоуровневые операции, например чтение build events, по-прежнему могут вернуть 403. Это ограничение конкретного вызова: проверять отдельно и не требовать повторного подключения всего аккаунта без причины. Параметр обязательного teamId у других инструментов не выдумывать и не заменять чужим ID.

## Почему появлялись ошибочные сборки

Git integration пыталась публиковать также Telegram-ветки общего репозитория. Для одной такой сборки подтверждён `missing_pages_app`; это не ошибка уже опубликованной главной. При проверке версия `main/c904e51` имела READY.

В проекте отключены автоматические preview deployments. Рабочие ветки проверяются Actions, затем готовая версия объединяется в `main` и автоматически публикуется один раз. Стандартный workflow не создаёт деплой, не коммитит и не пушит файлы.

В `web/vercel.json` сохранён Ignored Build Step:

```sh
git diff HEAD^ HEAD --quiet -- .
```

Команда выполняется из Root Directory `web`. Нет изменений в сайте — код 0 и сборка пропускается; есть изменения — код 1 и сборка продолжается. При недоступном родительском коммите ненулевой код разрешает сборку, а не скрывает изменение. Изменение только документации вне `web/` или Telegram не должно пересобирать сайт.

## Как смотреть правки

Проверки → объединение в `main` → Git deployment → подтверждение READY для нужного SHA → обновление постоянного адреса в браузере. Повторный ручной Deploy для уже запущенной сборки не нужен. Ошибочные старые сборки оставлены как история; они не заменяют успешную production-версию.

Источники: https://vercel.com/docs/project-configuration/vercel-json и https://vercel.com/kb/guide/how-do-i-use-the-ignored-build-step-field-on-vercel
