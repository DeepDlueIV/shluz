# NoClip — первая версия сайта

Главная и минимальный гостевой экран в существующем репозитории `shluz`. Backend, учёт аккаунтов, лимиты и биллинг остаются ответственностью шлюза.

## Запуск

### Windows: двойной щелчок

Установите **Node.js 24 или новее вместе с npm**, затем откройте **`START-WEBSITE.cmd` в корне репозитория** двойным щелчком. Запускатор установит зависимости через `npm ci` и откроет сайт в браузере после его готовности. Первый запуск требует интернета; последующие используют установленную копию, пока `package.json`, `package-lock.json` и версия Node.js не изменились. При ошибке окно останется открытым с сообщением.

Оставьте окно запускатора открытым. Для остановки нажмите **Ctrl+C**; если Windows спросит о завершении пакетного файла, ответьте **Y**. Сервер доступен только на этом компьютере по адресу `http://127.0.0.1:3000`; если порт занят, выбирается свободный из диапазона 3001–3010. Папка проекта может содержать пробелы. Перед повторным запуском остановите предыдущий сервер.

Запускатор работает с текущими файлами и не обновляет репозиторий через Git. Для новых версий сначала обновите рабочую копию обычным способом. Это локальный режим разработки: он работает, пока открыто окно. Для постоянного адреса сайта см. [публикацию на Vercel](./VERCEL.md).

### Из терминала

Нужны Node.js 24+ и npm. Команды из каталога `web/`:

```sh
npm ci
npm run dev
```

Адрес: http://localhost:3000. Production: `npm run build`, затем `npm start`.

## Что реализовано

- `/`: предоставленный видеофон, логотип, примеры запросов; одно поле ввода плавно превращается в закреплённую навигацию при прокрутке. Настоящий `backdrop-filter` размывает содержимое позади панели.
- Нижняя часть: ленты моделей, пять демонстраций, варианты доступа, пример API, описание и подвал. Материалы временные; примеры не выдаются за результат реального запроса.
- `/app`: перенос вопроса в памяти приложения, состояния подготовки, проверки браузера, потокового ответа, ошибки, остановки и исчерпания лимита.
- Адаптивная вёрстка. При `prefers-reduced-motion` фон заменяется постером, а длинная презентация — последовательными блоками. На невысоких экранах используется та же последовательная структура.
- Вход, OTP, оплата, полный кабинет, отдельные страницы и демонстрации десктопа/Telegram остаются для следующих итераций.

Стек: Next.js App Router, React, TypeScript, CSS Modules, Motion. Версии закреплены в `package-lock.json`. Дополнительной базы аккаунтов и серверного приложения здесь нет.

## Подключение шлюза

По умолчанию `NEXT_PUBLIC_GATEWAY_ENABLED=false`. В этом режиме вопрос остаётся в памяти вкладки и показывается сообщение о недоступности демонстрации. Сетевых запросов к шлюзу и выдуманного ответа модели нет. Обновление страницы очищает вопрос.

Для интеграции создайте `.env.local` по `.env.example`. После настройки сервиса задайте `NEXT_PUBLIC_GATEWAY_ENABLED=true` и пересоберите сайт: публичный флаг встраивается в клиентскую сборку. Секретные ключи провайдеров в web-переменные не передаются.

Рекомендуется общий HTTPS origin с reverse proxy: сайт и `/v1/web/*` доступны на одном домене. Proxy должен сохранять streaming без буферизации. Для Node-развёртывания предусмотрен `SHLUZ_GATEWAY_ORIGIN`, который включает Next rewrite. Для статической сборки маршрутизацию к API выполняет внешний reverse proxy. Самостоятельно менять cookie/CORS/Turnstile-политику шлюза не следует.

Проверенный контракт: [`web-access-v1.1`](https://github.com/DeepDlueIV/shluz/blob/432066135e0a8ab91ae960e6a4c3a6681f9d58ad/docs/CLIENT_API.md), сценарий — [`guest-dashboard-journey.md`](https://github.com/DeepDlueIV/shluz/blob/432066135e0a8ab91ae960e6a4c3a6681f9d58ad/docs/guest-dashboard-journey.md). Этот контракт находится в более новой ветке шлюза, чем исходный `main` данной веб-ветки; backend-ветки автоматически не объединялись.

Порядок действий:

1. Открытие страницы может вызвать `POST /v1/web/session`; это только браузерная сессия.
2. Отправка сохраняет вопрос в памяти и открывает `/app/`; текст не попадает в URL или browser storage.
3. На `/app/` проверяются фактический остаток через `/v1/web/me` и Turnstile с `action: demo_chat`.
4. Единственный `POST /v1/web/chat/completions` передаёт только `prompt`, `request_id`, `turnstile_token`. CSRF — в `X-CSRF-Token`, сессия — в cookie. Аккаунт создаётся шлюзом только после допуска запроса.
5. SSE завершается успешно только после `[DONE]`. Ошибка, ранний EOF или StrictMode replay не вызывают автоматического повторного POST.

При регистрации на новый email сервер сохраняет guest Account и учёт расходов. Фронтенд это поведение не дублирует. Live-проверка HTTPS/Origin, Turnstile, реальной генерации, SMTP и upgrade учётной записи в этой итерации не выполнялась.

## Проверки

```sh
npm run typecheck
npm test
npm run build
```

Тесты проверяют SSE с разрывами UTF-8/CRLF, обязательный `[DONE]`, ошибки потока, отмену, точный guest payload, cookie/CSRF и отсутствие автоматического повторного POST. Сеть и платные генерации в тестах не используются.

Визуальная проверка в браузере остаётся открытой: в текущей среде отсутствовал `control-browser`, обязательный для preview по инструкции Sites. До публикации проверить главную на desktop и телефоне, скролл в обе стороны, ввод, переход в `/app/`, скрытое меню, `prefers-reduced-motion` и отказ autoplay.

Для автономного статического просмотра:

```sh
NOCLIP_STATIC_EXPORT=1 npm run build
python -m http.server 8000 --directory out
```

Открыть http://localhost:8000. Каталог `out/` рассчитан на HTTP, а не двойной клик по HTML. В статическом режиме Next rewrites не работают. Метаданные пока содержат `noindex, nofollow` для первой итерации.
