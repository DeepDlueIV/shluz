# NoClip / SHLUZ — единый portable-лаунчер (Windows)

**Откройте NoClip.cmd в папке `D:\NoClip\Shluz`.**
Распакуйте туда весь проверенный архив `NoClip-SHLUZ-Portable.zip`, сохраняя структуру.
Нужны Python 3.12+ и Docker Desktop (Linux/x64). Управляется только существующий
owner-проект `shluz-owner-check`; другие контейнеры не затрагиваются.

Меню: статус, старт Gateway + Telegram, остановка, backup, Mini App отдельно,
остановка Mini App и возврат бота, установка/обновление, импорт из AppData.

## Где хранятся данные

Новая папка содержит `config/`, `versions/`, `backups/`, `miniapp-trial/`,
`runtime.json`, `installed.json`, `migration.json`. Старые файлы
`%LOCALAPPDATA%\Shluz` при первом запуске только КОПИРУЮТСЯ с SHA-256,
никогда не удаляются и не перезаписываются при конфликте. Исходные файлы
оставьте на месте до полной проверки нового запуска и независимого backup.

**Docker volumes, images и containers остаются в Docker Desktop.**
Перенос папки на другой компьютер сам по себе НЕ переносит базы данных Docker.
Никаких `docker down -v`, удаления volumes или массовой очистки.

## Действия

- Start запускает существующие контейнеры по Docker ID: Gateway, проверка healthy,
  затем классический Telegram-бот. Если контейнер отсутствует, не создаёт пустую БД.
- Stop останавливает бота, затем Gateway, не удаляя их. Если Mini App активна,
  сначала пытается вернуть исходный polling-бот и его Telegram-кнопку.
- Backup сохраняет согласованную копию SQLite с временной остановкой, проверяет
  наличие архивов необходимых volumes и возобновляет ранее работавшие процессы.
- Mini App — отдельная owner-only проба с временным HTTPS-туннелем и копией истории.
  На время пробы обычный polling-бот остановлен; она работает в отдельном окне.
  Закрывайте через Stop из меню. Генерации в Telegram тратят обычную квоту.
- Update вызывает существующий проверенный preview-updater и создаёт независимый
  backup заранее даже при повторном применении той же версии. Docker Compose
  после установки использует portable-настройки. Первоначальный AppData не удаляется.

**Восстановление базы из backup поверх существующих данных не автоматизировано:**
оно может уничтожить новые записи и требует отдельного согласованного восстановления.

## Секреты и ограничения

Никогда не загружайте `config/`, `backups/`, `miniapp-trial/trial.env` в GitHub
или чат. Храните папку локально, с доступом только вашей учётной записи Windows.
История и резервные копии не имеют собственного E2EE.
Старый `Shluz.cmd` не изменён и по умолчанию читает прежний AppData.
Не используйте одновременно оба разных механизма обновления.

Тесты CI не заменяют проверку реального запуска Docker Desktop, Telegram
и Mini App на вашем компьютере. Venice API здесь не тестируется.
