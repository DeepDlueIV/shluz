# NoClip / SHLUZ — актуальный portable-лаунчер (Windows)

**Один файл — `D:\NoClip\Shluz\NoClip.cmd`. Двойной щелчок запускает Gateway и НОВЫЙ Telegram с Mini App автоматически.** Не нужно выбирать пункты меню, отдельно открывать бот или Mini App, вручную управлять Docker.

## Что находится в папке

`NoClip.cmd` — основной запуск. `Stop-NoClip.cmd` — остановить шлюз, Mini App и HTTPS-туннель. `Status-NoClip.cmd` — состояния. `Backup-NoClip.cmd` — архив базы и настроек. Остальные `.py` — проверенный код управления; их вручную открывать не требуется. Не копируйте отдельно одни `.cmd`: распакуйте **весь** ZIP.

Нужны Docker Desktop (Linux/x64), Python 3.12+ и доступ к GitHub Release, Telegram API и Cloudflare. Все эти программы используются локально; сервисы SaaS на Vercel здесь не меняются.

## Новый Telegram — постоянный, а не тестовый

Уже опубликованный проверенный образ `preview-c47ff5b8` содержит актуальную Mini App и последние изменения шлюза. Лаунчер сверяет проверенный image SHA/digest и запускает новый Telegram с `TELEGRAM_INTERFACE=miniapp`, для **всех авторизованных пользователей**, а не только для владельца. Cloudflare Quick Tunnel создаёт временный HTTPS и кнопка «Меню» меняется в Telegram автоматически. Это временный dev-HTTPS: при новом запуске адрес может измениться, и лаунчер обновит кнопку. Для постоянного внешнего размещения позже понадобится стабильный домен/туннель.

**Прежний Docker-контейнер Telegram НЕ удаляется:** он выключен и остаётся резервным. Новый контейнер использует **тот же существующий Telegram volume с диалогами**, настройки Gateway и текущие разрешения аккаунтов. История не копируется во второй независимый аккаунт. Два polling-процесса одного BotFather token одновременно не запускаются.

При первом переключении выполняется проверенный backup существующих Docker volumes и `config`. После сбоя возвращается классический бот, если он работал до переключения. Для ручного возврата есть команда `NoClip.cmd --rollback`; это **не удаляет** историю нового режима или базы.

## Данные и портативность

Новые локальные `config/`, `versions/`, `backups/` и `live-miniapp/` находятся рядом с `NoClip.cmd`. Импорт из существующего контейнера переносит только необходимые настройки; **гигабайты старых версий и резервных архивов из AppData не перекачиваются автоматически**. Старую папку `%LOCALAPPDATA%\Shluz` не удаляйте до приёмки. Docker volumes, образы и контейнеры по-прежнему хранятся в Docker Desktop — папка с `.cmd` не заменяет резервное копирование Docker.

Секреты `config/`, `live-miniapp/live.env` и `backups/` никогда не загружайте на GitHub и не присылайте в чат. Ключ Venice остаётся на стороне Gateway. Проверьте, что доступ к папке есть только у вашей учётной записи Windows; лаунчер пытается ограничить ACL дополнительного Telegram env-файла.

## Сайт и отдельный туннель

В репозитории `main` уже существует отдельный защищённый Vercel ↔ ngrok bridge (`web/tunnel/`). **Он не подключается автоматически**: нужны локальные credentials ngrok, Vercel env, Turnstile и живой E2E-тест. Быстрое включение сайта без этих проверок открыло бы неправильно защищённый API. Туннель Mini App и туннель сайта — разные маршруты.

## Ограничения приёмки

CI проверяет код, архив, безопасные остановку/восстановление и изоляцию. Настоящий первый запуск на конкретном Windows-ПК, Telegram BotFather и Cloudflare HTTPS из вашей сети нельзя считать подтверждёнными до локального запуска. Если проверка не прошла, старые Docker volumes не удаляются. Не используйте старый `Shluz.cmd` одновременно с новым, иначе он может перезапустить резервный classic-бот.
