# Shluz — обновить и открыть

**Windows: распакуйте архив и дважды нажмите `Shluz.cmd`.**
Нужны уже установленные Python 3.12+ и работающий Docker Desktop в режиме Linux/x64.
Выбирать ветку, переносить файлы проекта и запускать тесты не нужно.

Запускатель получает последнюю **опубликованную и проверенную** сборку из постоянного
канала `preview`, проверяет SHA-256 архива и ID Docker-образа, автоматически находит
прежний проект `shluz-owner-check`, сохраняет его настройки и тома, делает резервную
копию перед миграцией, обновляет шлюз с ботом и открывает `http://127.0.0.1:18000/admin`.
Другие Docker-проекты он не удаляет. Исходники доступны в том же GitHub Release.

## Где теперь настройки

`%LOCALAPPDATA%\Shluz\config` — отдельное постоянное хранилище `.env.owner`,
`.env.telegram` и необязательного старого списка доступа. При первом запуске они
импортируются из существующих контейнеров/папок автоматически; следующие обновления
их не перезаписывают. Локальному Codex нужно работать с этой папкой после перехода
на запускатель, а не менять старые распакованные ZIP. Пароли сюда не присылайте.

Если старой установки нет, создаётся новый локальный mock-шлюз; случайный пароль
для логина `owner` записывается в `config/.env.owner`. Первичное создание бота и ввод
личного BotFather-секрета выполняет локальный Codex по вашему разрешению. Telegram
не включается без его конфигурации. Работающий бот не создаётся заново.

## Версии, данные и ошибки

`installed.json` содержит ревизию последнего успешного обновления; короткая ревизия
показана также внизу админки. `versions` содержит загруженные проверенные образы,
`backups` — согласованные копии остановленных SQLite-баз, служебного ключа и настроек.
Backups содержат личные данные и секреты: не публикуйте их и ограничьте доступ к папке
учётной записью Windows. Сохраняйте также независимую копию вне этого компьютера.

Если скачивание/проверка архива не удалась, старая версия остаётся запущенной.
Если не удалась резервная копия, миграция не запускается, прежние процессы включаются.
После сбоя уже начатой миграции **не обещается автоматический откат кода**: Codex
проверяет резервную копию и совместимость схемы; восстановление поверх новых данных
требует согласия владельца. Не удаляйте Volumes и не делайте `down -v`.

Обновление требует места под образ и базы. Автоматическое удаление старых backups
не выполняется. При нехватке места или другой ошибке передайте текст окна Codex:
обычные команды/сравнение конфигураций владельцу не поручаются.

Это запускатель **локального owner-контура на SQLite**. Он не мигрирует внешнюю
PostgreSQL/Supabase, не переносит рабочую базу клиентов и не добавляет ещё не созданный
сайт. ARM/Windows containers не поддерживаются этой сборкой. Недоступность Telegram
из вашей сети остаётся внешним условием; запускатель не меняет VPN/антивирус.

## Как появляется обновление (для разработчика)

CI → тесты Python/Chromium/Windows/PostgreSQL → Docker upgrade smoke с восстановлением
копии старой схемы → готовый архив образа → неизменяемый Release `preview-COMMIT` →
манифест `preview/manifest.json`. Публикация разрешена только доверенным push в этом
репозитории, не любому PR/форку. Текущие доверенные ветки указаны в CI и publisher.
Другой разработчик меняет список доверенных публикаций при необходимости, не
настройки владельца. Новая рабочая ветка сама по себе не становится обновлением.

В этой версии образ хранится как архив в GitHub Release, а не в GHCR: так первый
локальный запуск не зависит от прав видимости пакета/авторизации в registry.
`docker load` загружает заранее собранный образ, локальной сборки нет.
Целостность: HTTPS GitHub/CDN + checksum + pinned image ID; отдельной цифровой подписи
изолированным ключом пока нет. Компрометация доверенного репозитория — граница доверия.
