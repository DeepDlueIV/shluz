# Уточнения владельца: демо, аккаунты, оплата и обновления

18.10.2026, после установки Codex версии 619374f. Это требования и предложения;
не выдавать записанное за уже реализованный код. При конфликте с прежней концепцией
«только приглашения/заявки» для конечного продукта приоритетны уточнения ниже.

## Принятые владельцем требования

- Start в Telegram должен автоматически регистрировать пользователя и назначать
  ограниченный демо-тариф. Веб тоже должен иметь демо. Демо-модель выберет владелец.
  Повторный Start не создаёт второй аккаунт и не сбрасывает демо-остаток.
- После подтверждённой будущей оплаты назначается другой тариф с большим списком моделей.
  Политики demo и paid, число запросов, максимум контекста/ответа и глобальный бюджет
  задаются шлюзом, а не только скрытием кнопок. Текущего monthly_request_limit недостаточно
  для разового пожизненного демо: не превращать «пару запросов» в повторяющийся каждый месяц бонус.
- Список моделей Telegram будет заметно меньше desktop. Списки/цены владелец предоставит
  позже. Не разрешать весь каталог Venice автоматически и не принимать model ID в обход тарифа.
- Оплата: сейчас только меню тарифов и кнопка «Оплатить» с честным состоянием «ещё не подключена».
  Не назначать paid-тариф по нажатию кнопки. Не реализовывать Telegram Stars, внешний
  процессинг, фиктивное подтверждение или выбор платёжного провайдера. Владелец даст API позже.
- У пользователя могут быть независимые аккаунты email и Telegram. Не склеивать их автоматически
  по имени, email из непроверенного источника или схожести профиля. Будущий login через Telegram
  на сайте — официальный Telegram Login с серверной проверкой, а не обычная ссылка Start.
- Настройку, тесты и обновление выполняет разработчик/локальный Codex; владелец смотрит готовый UI.
- Обсуждение решений: Grill Me / grilling, готовые варианты и рекомендация. Не спрашивать
  то, что можно узнать по коду; не превращать вопросы о бизнес-решениях в поручение диагностики.
- Supabase без подписки — ограничение бюджета. Применение платного тарифа не согласовано.

## Что пока не решено

Число/срок демо, конкретная демо-модель, наборы по каналам, должен ли Telegram-вход
на сайте открывать тот же Telegram-аккаунт, окончательная БД и платёжный шлюз.
Раздельность email и Telegram уже разрешена; не спрашивать это повторно.

## Обновления: предложение для согласования

Разрабатывать весь stack можно в любых ветках. Текущая implementation/telegram-beta-complete
содержит шлюз, бота и общие файлы; её имя не ограничивает содержимое Telegram.
Запускатель должен брать НЕ случайную «самую свежую ветку», а опубликованный пакет
из фиксированного канала `preview` (проверка владельцем) или `stable` (принятый релиз).

Разработчик после тестов публикует manifest: версия, commit SHA, контрольные суммы
и закреплённые digest образов шлюза/бота. Публикация из доверенной ветки — отдельное
правило, не из любого PR/форка. Имя ветки не входит в пользовательскую настройку.
Если разработчик откроет новую ветку, запускатель продолжает видеть прежний канал;
незаконченные изменения не попадают к владельцу до публикации.

Двойной клик: версия → backup до миграции → получение пакета → согласованное обновление
stack → проверка запуска → открытие админки. Секреты/данные вне каталога обновлений.
Откат кода после необратимой миграции не обещать: нужен совместимый schema rollback
или восстановление заранее проверенной резервной копии с явным предупреждением о новых данных.
Запускатель ещё не реализован. Не менять ветки/релизы автоматически этим документом.

## Риск внешней оплаты: только фиксация, без реализации

Владелец не выбирает Stars. Это соблюдается в коде. При этом внешняя платёжная система
сама по себе не отменяет действующие правила Telegram для продажи цифровых услуг
внутри ботов/mini-apps. Перед включением настоящей оплаты проверить допустимый UX
по актуальным правилам; не обещать соответствие на основании одной внешней ссылки.

Источники:
- https://core.telegram.org/bots/telegram-login — официальный вход и проверка ID token.
- https://core.telegram.org/bots/payments-stars — опубликованные требования Telegram.
- https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases
- https://github.com/mattpocock/skills/blob/main/skills/productivity/grilling/SKILL.md
