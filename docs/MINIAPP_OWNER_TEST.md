# NoClip: проверить Mini App у себя

## Три действия

1. Docker Desktop и обычный шлюз должны работать. Распакуйте весь архив проверки.
2. Дважды нажмите **Start-MiniApp.cmd**. В первый запуск сборка скачивается автоматически.
   Если архив не содержит ваш ID, один раз укажите числовой Telegram ID из «Пользователи».
3. Откройте своего бота в Telegram → **Меню** у строки ввода. При необходимости отправьте
   `/start` один раз. Панель: диалоги, модели, настройки, аккаунт. Промпты пишите в чат.

Окно Start оставьте открытым. Чтобы закончить, нажмите **Enter в нём** или откройте
**Stop-MiniApp.cmd**. После аварийного закрытия окна также используйте Stop.
Не открывайте обычный Shluz.cmd одновременно с тестом: два polling-процесса одного
бота конфликтуют. Если компьютер перезагрузился, сначала Stop, затем обычный Shluz.cmd.

## Что происходит

Запускатель находит действующие контейнеры `shluz-owner-check` автоматически.
До остановки бота проверяет настройки, связь с Telegram и скачанную сборку.
Новый токен BotFather не нужен; секреты остаются на компьютере и не печатаются.

Старый бот временно остановлен, не удалён и не пересоздан. Вместо него работает
кандидат **только для вашего Telegram ID**. Другие пользователи во время проверки
ответов не получают; им не назначаются новые права. После Stop прежняя работа возвращается.
Глобальное меню и команды Telegram не меняются: новая кнопка назначается только вам.

История копируется в отдельный Docker-том. Удаление/переименование в Mini App меняет
только эту копию. Она сохраняется между тестовыми запусками; в старую базу обратно
не переносится. Старые вопросы/ответы в Telegram не удаляются массово.

Шлюз и его база не обновляются. **Ваши вручную отправленные промпты используют прежний
тариф, квоту и баланс; ответы настоящей платной модели стоят денег.** Сам запуск и
нажатия меню не делают генераций. Новый тариф/модель/доступ автоматически не выдаётся.
Проверку расчётов провайдера не заменяет проверка интерфейса.

## HTTPS и границы безопасности

Временный Cloudflare Quick Tunnel даёт панели HTTPS без домена и регистрации.
Cloudflare — внешний участник передачи данных (TLS завершается на его стороне);
это не E2EE. Случайный URL не считается защитой. Данные доступны только после проверки
подписи Telegram initData и совпадения с ID владельца. Существующие права шлюза
проверяются при действиях. Пользовательский ID нельзя подменить полем формы.

Туннель ведёт только к Mini App listener контейнера. `/admin`, `/v1`, `/docs` на нём
отсутствуют. Порты на внешнем интерфейсе компьютера не публикуются. Шлюз, Docker socket,
Venice API-ключ и административные пароли туннелю не передаются.

При Stop сначала отключаются туннель и кандидат, затем возвращаются прежняя кнопка
и старый бот. Если сеть не позволила вернуть кнопку, Stop можно запустить повторно.
При недоступном Docker не удаляйте контейнеры/тома: снова откройте Docker, затем Stop.
Тестовая копия и файл восстановления лежат отдельно: `%LOCALAPPDATA%\Shluz\miniapp-trial`.

## Границы проверки

CI проверяет Python, Windows-запускатель, авторизацию, реальный Chromium + HTTP,
снимок/изоляцию в Docker и содержимое сборки. Это не живое открытие приложения на
конкретном телефоне/ПК владельца. Проверить: нижнее меню, создание/смена диалога,
настройки, возврат в чат, один разрешённый ответ, Stop и возврат старого бота.
Экспорт на отдельных Telegram WebView может требовать отдельной адаптации.

Официальные источники:
https://core.telegram.org/bots/webapps
https://core.telegram.org/bots/api#setchatmenubutton
https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/

Main и обычный preview не меняются. Шифрование хранения остаётся отдельной задачей;
десктопный SECURITY HOLD не обходится и запуск NoClip.exe для этого теста не нужен.
