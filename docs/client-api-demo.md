# Демо, модели и расходы: общий контракт для сайта/Telegram/desktop

Реализовано в обновлении launcher/demo/rights от 18.10.2026. Сайт и его авторизация
разрабатываются отдельно. Этот документ позволяет агенту сайта не создавать второй
биллинг и не редактировать код Telegram.

## Аккаунт и демо

В режиме `demo` новый Start через доверенный Telegram-бот создаёт аккаунт/identity и
`DemoGrant` автоматически, без приглашения или пользовательского JSON. По умолчанию
на аккаунт **3 запроса за всё время**, число изменяется в `/admin/access`.
Повторный Start, новый месяц, диалог, обновление и вход из другого канала не пополняют
пакет. При уменьшении настройки использованное число сохраняется: доступный остаток
может стать нулевым, отрицательных значений в интерфейсе нет.

Режим `closed` сохраняет приглашения/одобрение заявок для контролируемого теста.
Переключение режима регистрации не отзывает доступ уже одобренных аккаунтов: для
этого есть блокировка в панели. Старые аккаунты/подписки не заменяются демо миграцией.
Старый одобренный аккаунт с действующим тарифом продолжает его использовать.

Будущая веб-регистрация после подтверждения личности создаёт тот же `Account` и
использует `app.product.service.grant_demo` внутри транзакции. **Публичного endpoint,
принимающего произвольный Telegram ID без проверки, здесь нет.** Email/login и
официальная Telegram-авторизация браузера ещё не реализованы. Админский, bootstrap
или служебный ключ нельзя помещать в браузер. Независимый email-аккаунт возможен;
связывание двух существующих аккаунтов/кошельков не входит в это изменение.

## Чтение: персональная авторизация

- `GET /v1/me`: `plan.kind` = `demo` или `standard`; для демо `plan.id/code` = `demo`,
  `allowance.requests` содержит `limit/used/remaining`, `resets_at:null`, `scope:account`.
  Виртуальная demo-plan не является оплаченной подпиской в таблице Plan.
- `GET /v1/models`: только модели, разрешённые аккаунту **и** каналу. Пустой `data`
  означает, что сейчас нет доступных моделей, а не сетевую ошибку.
- `GET /v1/plans`: список активных тарифов с `id/name/monthly_price_usd`,
  `monthly_request_limit` и доступным для канала `models`. `payment.enabled:false`.
  Нажатие «Оплатить» не меняет подписку; внешнее платёжное API ещё не подключено.
- `GET /v1/me/usage?limit=20&offset=0`: свой текущий месяц UTC, сводка и страницы
  записей. Есть модель, канал, входные/выходные токены, `charged_usd` и
  `charge_status`, количество успешных запросов. Никогда не возвращает чужие
  аккаунты, провайдерский баланс/себестоимость, секреты или текст переписки.
  `charged_usd:null` / `charge_status:unknown` означает неизвестную сумму, не ноль.
  При частично неизвестной сумме summary даёт `known_charged_usd` и
  `unpriced_requests`. Демо для пользователя бесплатно даже при платном upstream.

Это **учёт списаний**, не готовый денежный кошелёк/пополнение. Выручка подписки и
списания за запрос различаются. Цена не выбирается разработчиком вместо владельца.
Все денежные значения JSON — decimal-строки, а не двоичные float.

## Проверка генерации в шлюзе

`POST /v1/chat/completions` — модель проходит пересечение списка канала и списка
тарифа (либо demo-models). `source` в теле не переключает права: канал приходит из
проверенной авторизации. Каналы: `telegram`, `web`, `harness`; старые `site`, `api`
и `desktop` приводятся к соответствующим каналам. По умолчанию везде **только mock-chat**.
Отсутствующий индивидуальный список тарифа наследует канал; явный пустой запрещает всё.

Проверка остатка/минутного лимита и резерв выполняются одной короткой транзакцией
(SQLite BEGIN IMMEDIATE; PostgreSQL advisory transaction lock). Обращения к модели
не держат эту блокировку. PostgreSQL-реализация сериализует admission на текущем
небольшом масштабе; без измерений не обещать неограниченную производительность.

Демо: максимум 24 000 символов с контекстом и 512 выходных токенов по умолчанию,
настраиваются в панели. `max_completion_tokens` передаётся провайдеру; сервер
отклоняет завышенный клиентский лимит до POST. Для standard сейчас верхний предел
выхода 4096, контекста 200 000 символов; настройка отдельных платных моделей позднее.
Глобальная защита demo: 100 попыток/сутки UTC; 30 запросов/минуту на аккаунт.
Это не полноценная защита от ферм аккаунтов. По умолчанию реальный Venice не включён.

Ошибки: `429 demo_exhausted`, `403 model_not_allowed`, `400 input_too_large`,
`429 request_rate_limited` (`Retry-After:60`), `429 demo_temporarily_unavailable`.
Старые ошибки подписок/ключей сохраняются. Неопределённый результат сети **не
отправляется повторно и не возвращает демо автоматически**: модель могла отработать.
Только однозначный отказ провайдера (ключ, баланс, rate limit) освобождает резерв;
это идемпотентно. Ручная отмена ожидания не обещает возврата расхода.

Миграция `20261018_07` добавляет продуктовую политику, lifetime-счётчик демо, правила
моделей и признаки в usage. Оплаченная месячная квота не включает демо-запросы.
Настоящие модели и окончательные списки по каналам задаёт владелец позже.
