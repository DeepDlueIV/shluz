# NoClip: управление вне переписки (Mini App v1)

## Утверждённый сценарий

Владелец выбрал вариант 3: обычный чат Telegram содержит вопросы и ответы модели,
а кнопка «Меню» рядом с вводом открывает отдельную Mini App. Навигация, модель,
диалоги, настройки и аккаунт не отправляют сообщений в переписку. Не переписываем
шлюз, биллинг или генерацию. Новый интерфейс — отдельная ветка
`feat/telegram-miniapp-control` от `f7b6d8f1`; старый бот/preview/main не заменяются.

## Техническое решение

- Опциональный режим `TELEGRAM_INTERFACE=miniapp`; по умолчанию `classic`.
- Небольшой FastAPI HTTP-сервер и статический интерфейс **в процессе бота**:
  общие Store, jobs и gateway. Нет второго polling, второй базы, копии диалогов
  или самостоятельной системы тарифов. Один процесс — существующий InstanceLock.
- HTTPS `/miniapp` нужен извне; `/miniapp/api/*` — только управление, не генерация.
  Публично не выкладываем, действующую кнопку бота без включения режима не меняем.
- Telegram initData проверяется HMAC, со сроком и защитой от дублированных полей;
  browser initDataUnsafe и переданный user_id не являются авторизацией.
  Короткая сессия Mini App хранится в памяти вкладки, без localStorage/URL.
- Каждый запрос перепроверяет право через шлюз; token Venice, connector и внутренний
  Telegram-токен в браузер не возвращаются. Закрытая бета остаётся закрытой.
- Действия над диалогом проверяют владельца. Во время генерации нельзя сменить
  диалог/модель или удалить историю. Stop относится к конкретному текущему запросу.
  Удаление требует одноразового подтверждения, связанного с актуальным состоянием.
- Все подтверждения видны внутри Mini App. Отдельные сообщения с меню и клавиатуры
  под финальными ответами в новом режиме не отправляются; временный индикатор
  генерации заменяется ответом или удаляется при завершении draft.
- Экспорт — скачивание файла из панели, не новое сообщение бота. При сбое платформы
  остаётся возможность скопировать экспорт, без обещания удаления истории Telegram.
- FAQ/поддержка/срок 30 дней доступны в панели. Не заявляем E2EE. Платёжный шлюз
  остаётся отключённым; выбор тарифа не меняет права и баланс.

## Проверка и включение

Сначала изолированные HTTP/бот/браузерные тесты. Живой Telegram Mini App требует
проверенного HTTPS-origin и настройки запуска. Новое поведение не доставляется
обычным preview-лаунчером до отдельного решения владельца. Откат — режим classic
и возврат старого образа без удаления томов. Проверить сброс MenuButtonWebApp
при переключении обратно. Старые сообщения/неизвестные клавиатуры массово не удалять.

Первичный источник: https://core.telegram.org/bots/webapps
(Menu Button, Validating data received via the Mini App).

## Контракт miniapp-v1

Origin единственный, из `TELEGRAM_MINIAPP_URL`. Путь `/miniapp` отдаёт панель.
POST требует точного Origin; same-origin GET может не содержать Origin, но требует
Bearer-сессию. Cross-site доступ не разрешён. Cache-Control: no-store. Access logs
HTTP-сервера отключены. Не добавлять логирование initData, Authorization или тел запросов.

- `POST /miniapp/api/session`: `{ "init_data": "<Telegram.WebApp.initData>" }`.
  HMAC-SHA256 по официальному алгоритму, auth_date не старше 5 минут, допуск часов
  вперёд 60 секунд. Ответ `{session, expires_in}` — bearer на 15 минут только для панели.
  Хранить в памяти; после истечения/перезапуска переоткрыть меню. Нельзя брать user_id
  из query/тела действий, `initDataUnsafe` или доверять присланному account_id.
- Остальные routes требуют `Authorization: Bearer <panel session>`; они заново
  проверяют существующее право Telegram через gateway, а не доверяют кешу панели.
- `GET state`: текущий диалог, метаданные списка, модель, стиль, ID NoClip,
  тариф/остатки, состояние запроса и срок истории. Без содержимого сообщений.
- `GET models`: фактические доступные модели Telegram/тарифа; клиент не назначает права.
- `GET account`: пользовательский расход и предложения тарифов. Оплата выключена.
- `POST action`: `{action, request_id, target?, value?, confirmation?}`.
  Actions: new, activate, rename, model, style, export, clear, delete, forget, stop.
  `request_id` — случайные 16–64 символа; повтор того же действия в пределах сессии
  не создаёт второй диалог. Хранятся 64 последних id. Новая сессия не обещает дедупликацию
  действий прежней вкладки. Ни один маршрут не вызывает платную генерацию.
- `POST confirm`: `{action: clear|delete|forget, target?}` → confirmation на 120 секунд.
  Подтверждение одноразовое, привязано к сессии/аккаунту/цели/состоянию истории. Новое
  сообщение/изменение истории делает его устаревшим. Для forget target пустой.
- target — реальный ID собственного диалога; для stop — ID текущего запроса из state.
  Stop отменяет ожидание через тот же Controller, без автоматического повтора или
  обещания бесплатного прерывания. Удаление/переключение при генерации запрещено.
- export возвращает `{text}` для скачивания Blob или копирования внутри панели,
  не отправляет документ в чат. Возможность скачивания зависит от клиента Telegram.
- Ответы: 401 — переоткрыть панель; 403 — доступ закрыт; 404 — чужой/удалённый объект;
  409 — устаревшее подтверждение/генерация/лимит диалогов; 422 — некорректный ввод;
  503 — шлюз недоступен. После сетевого сбоя не повторять изменение автоматически:
  сначала перечитать state. Секретные поля в ошибках валидации не возвращаются.

## Включение разработчиком после проверки HTTPS

Это инструкция будущего включения, а не утверждение, что live URL уже создан.

1. Сохранить согласованную копию томов и настроек. Выбрать эту ветку; не скачивать
   обычный owner preview поверх неё. Никакого `down -v`. Не запускать два polling
   процесса с одним bot token. Для полностью параллельной проверки — отдельный бот
   с собственной базой и gateway-окружением; не использовать реальные данные в CI.
2. Подготовить HTTPS origin, проксирующий **только** `/miniapp` и `/miniapp/*`
   на HTTP-порт бота 8081. Не публиковать `/admin`, gateway connector или всю сеть.
   Reverse proxy ограничивает body и частоту; этот сервис не является DDoS-фильтром.
3. `TELEGRAM_INTERFACE=miniapp`, `TELEGRAM_MINIAPP_URL=https://домен/miniapp`.
   При Docker использовать дополнительный `compose.owner.miniapp.yaml` с
   `NOCLIP_MINIAPP_URL` в локальном env. Порт на хосте привязан к 127.0.0.1:18081.
   Существующие TELEGRAM_BOT_TOKEN и gateway connector остаются только на сервере.
4. Runtime сначала запускает локальный HTTP-сервер, затем устанавливает нижнюю
   MenuButtonWebApp через Telegram API. Отдельный Client ID сайта/OTP не требуется.
5. Открыть Mini App из кнопки возле ввода. Проверить на мобильном и desktop Telegram:
   действия не создают сообщения, следующий prompt использует выбранный диалог,
   Stop, экспорт, повторное открытие. Telegram Web/iOS/Android могут различаться.

## Откат

Поставить `TELEGRAM_INTERFACE=classic`, убрать opt-in Compose override и запустить
**эту версию** один раз: она возвращает MenuButtonCommands. После этого при желании
вернуться на `f7b6d8f1`/старый preview. Данные совместимы: схема истории и шлюза не
менялась. Новая панель не удаляет неизвестные старые сообщения/клавиатуры массово.
Удаляется лишь прежняя известная служебная панель при /start или /menu; slash-команда
убирается по возможности. В обычной переписке остаются prompt/ответ и необходимые
сообщения об ошибке/прерывании, а не экраны навигации.

## Проверки

`pytest tests/telegram/test_miniapp.py` — подпись, срок, Origin, чужие диалоги,
повторные действия, подтверждения, отзыв доступа, изоляция, Stop и отсутствие
модельных вызовов при управлении. Старый classic покрыт прежними тестами.
`python scripts/verify_telegram_miniapp.py` — настоящий Chromium и изолированный
HTTP API; initData и Telegram transport тестовые, Venice только mock.
Ни frontend test fixture, ни программный HTTP override не являются production-флагом.
