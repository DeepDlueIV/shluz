# Первый живой тест Venice: локальный шлюз и Telegram

21.10.2026. Инструкция, не отчёт о выполненном запросе. В этой доработке ключи,
модель, рабочие доступы и реальный провайдер не переключаются.

## Владельцу: подключение без передачи ключа в чат

1. До переключения провайдера: «Демо и модели» → «Новые пользователи» →
   «Только приглашения и одобрение заявок» → сохранить. В «Telegram» оставить
   активный доступ только своему тестовому аккаунту; старые приглашения отозвать.
   Закрытый режим сам по себе НЕ отзывает доступы, выданные раньше.
2. В Venice для теста использовать отдельный Inference Only ключ с лимитом расходов
   на 24-часовой epoch (например USD 0.50; DIEM ограничить отдельно, если есть).
   Не ставить Admin и не считать остаток аккаунта лимитом отдельного ключа.
   Если прежний ключ уже публиковался в переписке, заменить его новым.
3. Win+R → `%LOCALAPPDATA%\Shluz\config` → открыть `.env.owner` в Блокноте.
   Добавить/заменить `VENICE_API_KEY=...`, без `Bearer` и пробелов. Удалить старую
   строку `SHLUZ_VENICE_API_KEY`, если она есть: она приоритетнее. Не менять пароль,
   database URL, bootstrap token или настройки бота. Ключ НЕ нужен в `.env.telegram`.
4. Для подключения заменить существующее `SHLUZ_ACTIVE_PROVIDER=mock` на
   `SHLUZ_ACTIVE_PROVIDER=venice`, сохранить и открыть обычный `Shluz.cmd`.
   Compose применит изменённый env при запуске, без удаления томов. Открыть
   «Поставщик»: наличие каталога не доказывает принятие ключа; проверить доступность
   расходования/баланс. Недоступность расширенной аналитики с Inference Only возможна.

## Перед первым сообщением

Не тестировать на безлимитном тарифе. Создать/назначить только своему аккаунту отдельную
подписку «Тест Venice» на 2 запроса и небольшой бюджет. В «Демо и модели» разрешить
ОДИН точный ID из каталога и для канала Telegram, и для этого тарифа. В тарифах других
активных пользователей убрать наследование платного каталога либо закрыть их доступ.
Публичное демо не расширять; оставшийся mock-chat не превращается в модель Venice.
В боте выбрать разрешённую модель заново — старая выбранная mock-chat автоматически
не подменяется платной моделью.

«Unlim» в «Тарифы и оплата» — название предложения, не название модели и не выданное
право. Текущий callback «Оплатить» ничего не назначает; право меняется через админку
или явно выданное приглашение. Не рассылать приглашение с безлимитным тарифом.

Первый текст: «Ответь одним коротким предложением: связь работает». В коде недемо-
запрос ограничен 4096 выходными токенами; просьба о краткости сама по себе не лимит.
Для технического теста с меньшим лимитом агент передаёт `max_completion_tokens=128`
в отдельный запрос к шлюзу, а не повышает лимиты или повторяет генерацию автоматически.
Месячный бюджет подписки проверяется перед запросом и не обещает абсолютно точного
жёсткого потолка его окончательной себестоимости. Ограничение самого Venice-ключа —
дополнительный простой предохранитель. Для PAYG нужны проверенные ценовые bounds;
на первом тесте не обходить их для «удобства».

## Что проверяет разработчик

Через разрешённый доступ к локальной среде: read-only проверка ключа и каталога,
один ограниченный запрос через шлюз (не прямой probe вместо интеграции), фрагменты
SSE/Telegram, запись токенов и стоимости. Отдельный согласованный запрос — Stop и
сверка резерва/списания. Результат неизвестен — так и записывать, не как нулевой расход.
Ключи, тексты, account IDs и сырые env/config не публиковать. После теста вернуть
`SHLUZ_ACTIVE_PROVIDER=mock` и снова открыть `Shluz.cmd`, если платный контур не нужен.

У среды ChatGPT нет доступа к Docker владельца; изменение GitHub не подключает его
ключ. Владелец оценивает ответ и UI, агенты проводят технические проверки там, где
есть доступ к сети и локальным секретам. Нельзя выдавать mock или прямой Venice-probe
за успешно проверенную связку Telegram → шлюз → Venice.

## Диагностика отказа Venice (23.10.2026)

В админке откройте **Поставщик → Генерация разрешена**. Это результат
бесплатного `GET /api_keys/rate_limits` на **серверном ключе**, а не факт наличия
`VENICE_API_KEY` или доступности публичного `GET /models`. Ключи не передавайте в чат.

- **Да**: общий доступ ключа разрешён, но отдельная модель ещё может быть запрещена
  (ограничения `modelPrivacy`, регион, подписочная/модельная политика). Проверьте
  ID выбранной модели и ограничения ключа на venice.ai/settings/api.
- **Нет**: генерация для данного ключа запрещена; проверить срок, разрешения,
  установленный лимит USD/DIEM и баланс.
- **Не удалось проверить / 401**: проверьте, какой ключ реально загрузил шлюз.
  Не перепутайте `VENICE_API_KEY` с приоритетным `SHLUZ_VENICE_API_KEY`.
  Полный ключ после выпуска в Venice не восстанавливается: при утрате/отзыве
  создайте новый Inference Only с небольшим лимитом. Только после этого обновите
  локальный `.env.owner` и перезапустите штатным `Shluz.cmd`, не удаляя тома.

Ответы `401` на генерацию могут означать неверный ключ **или** ограничение
доступа к модели; `403` — запрет модели/ключа/региона. Не утверждать по одному
статусу, что секрет непременно неверен. Отсутствие баланса или аналитики в админке
с Inference Only ключом ожидаемо: `/billing/*` требует Admin, сама генерация нет.
Код обращения нужен для поиска по журналу шлюза, а не для извлечения секрета.
Не повторять платный запрос автоматически для диагностики.
