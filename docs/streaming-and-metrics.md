# Потоковые ответы, диагностика и безопасное обновление

Реализация 19.10.2026. Относится к gateway и Telegram; каталог `web/` не изменяется.
Публикация кода не является установкой на компьютере владельца. Реальный провайдер
не включается этим обновлением; `mock-chat` остаётся единственной моделью по умолчанию.

## Пользовательский результат

Шлюз передаёт фрагменты ответа по мере поступления, а не разбивает уже готовый ответ.
Telegram читает этот поток и редактирует один предварительный текст не чаще примерно
раза в 1,2 секунды. Этот рабочий интервал не является гарантией лимитов Telegram:
при ограничении отправки обновления объединяются, чтение модели не блокируется.
Кнопка отмены сохраняется. Итоговое сообщение использует прежние форматирование,
разделение длинного текста и отправку файла. Для очень длинного потока показывается
ограниченный префикс с предупреждением: весь текст придёт после завершения.
При обрыве пользователь видит сохранённый префикс и предупреждение, не фиктивное
«успешно». Частичный текст не считается завершённым ответом в истории диалога.

Venice adapter поддерживает настоящий `stream:true` и запрашивает `include_usage`.
Синтетический mock тоже выдаёт последовательные фрагменты с задержкой, поэтому
приёмку транспорта/отмены можно выполнить без денег и ключа поставщика.

## HTTP-контракт для сайта и desktop

Использовать `POST /v1/chat/completions`, обычную персональную авторизацию и
`stream:true`. `stream_options: {"include_usage": true}` добавляет итоговый usage.
Браузерный клиент читает ответ через streaming fetch/ReadableStream; обычный
EventSource не подходит для этого POST с телом. Авторизация браузера и защита
сессии — работа сайта, секрет поставщика или админа в него не попадает.

Успешное начало: HTTP 200, `Content-Type: text/event-stream`, `Cache-Control: no-store`,
`X-Accel-Buffering: no`. Reverse proxy также не должен буферизовать этот маршрут.
SSE-события разделены пустой строкой, поле `data` содержит JSON:

```text
data: {"id":"chatcmpl-...","object":"chat.completion.chunk","created":0,"model":"mock-chat","choices":[{"index":0,"delta":{"content":"Привет"},"finish_reason":null}]}

data: {"id":"chatcmpl-...","object":"chat.completion.chunk","created":0,"model":"mock-chat","choices":[{"index":0,"delta":{},"finish_reason":"stop"}]}

data: {"id":"chatcmpl-...","object":"chat.completion.chunk","created":0,"model":"mock-chat","choices":[],"usage":{"prompt_tokens":0,"completion_tokens":0,"total_tokens":0}}

data: [DONE]

```

Идентификаторы/created выше — пример формата, не реальные значения запроса.
Фрагменты TCP могут разрезать UTF-8, строку или событие; клиент собирает SSE-кадры,
а не считает каждое сетевое чтение завершённым JSON. Пустые choices допустимы.
Успешный `[DONE]` передаётся только после завершения учёта. При отсутствии итоговой
статистики поставщика `usage:null`: не вычислять реальные токены по длине текста.
Денежные данные находятся в личном API расходов, не копируются из provider JSON клиенту.
`stream:false` по-прежнему возвращает обычный JSON.

До начала передачи ошибки прав, демо и провайдера возвращаются обычным HTTP JSON
с прежними 4xx/5xx. После начала HTTP-код изменить нельзя: при доступном соединении
передаётся `data: {"error":{"code":"stream_interrupted",...}}`, затем поток закрывается
**без `[DONE]`**. Необъяснённое закрытие/тайм-аут также не является успехом.
POST автоматически не повторять: предыдущий запрос мог быть оплачен провайдеру.
Клиентская отмена закрывает upstream, но не гарантирует прекращения расчёта на его сервере.
Наличие частичного текста нельзя интерпретировать как отсутствие расходов.

## Права, расход, обрывы

Поток использует тот же шлюзовой admission/резерв, тариф × канал и lifetime demo,
а не отдельный обходной маршрут. В тело запроса нельзя подставить другой канал.
Префикс Telegram и сайт не управляют собственной независимой квотой.
Проверки размера ввода и максимума выхода сохраняются. Bootstrap — служебный доступ,
не способ авторизовать публичный интерфейс.

Один запрос финализируется одним UsageEvent. Прерванный поток имеет `interrupted`,
не `success`; неопределённые токены/стоимость отмечаются как неизвестные. Запрос и
демо не возвращаются автоматически; резерв кредитов неопределённого запроса
сохраняется в текущем месячном лимите. Однозначный отказ по ключу, балансу или
лимиту провайдера до передачи имеет прежнюю политику отказа, без генерационного retry.
Сбой самого процесса/БД не даёт гарантии exactly-once: pending-записи всё ещё требуют
предусмотренного контроля/сверки. Не обещать автоматическую сверку счетов Venice.

`GET /v1/me/usage` дополнен `usage_known`, `duration_ms`, `first_token_ms` для записи;
токены могут быть null. Summary суммирует известные токены и отдельно возвращает
`usage_unknown`; USD с неизвестными значениями остаётся неизвестным, не нулевым.
Демо бесплатно пользователю, хотя себестоимость поставщика может существовать.
Это учёт, не готовый кошелёк и не интеграция платежей.

## Диагностика владельца

Раздел **«Диагностика»**: `/admin/diagnostics`, защищён той же авторизацией админки.
Данные `/admin/diagnostics/data` также закрыты. Показываются последние 24 часа,
не более 2000 последних принятых запросов (ограничение выборки явно отображается).
По модели/поставщику/каналу: число запросов и ошибок/обрывов, среднее время до
первого **текстового** фрагмента, среднее полное время и p95 выборки, известные
входные/выходные токены, себестоимость USD и число неизвестных измерений.

Первый текст измеряется на шлюзе: от получения запроса до первого content delta;
это не подтверждение доставки сообщения Telegram или отрисовки браузера.
Полное время учитывает генерацию до финализации/обрыва. Для старых записей без
измерений показано «—». Для непотокового ответа время первого фрагмента отсутствует.
Пользовательский текст, ключи и ID пользователей не записываются в метрики/spans.
Отказ до создания резерва учитывается в OTel, но не входит в таблицу принятых запросов.
Системные исключения транспорта не копируются в публичную ошибку.

OTel SDK инструменты: `shluz.requests`, `shluz.request.duration`,
`shluz.request.first_token`, `shluz.tokens`, `shluz.provider.cost`,
`shluz.requests.active`; trace `chat`. Атрибуты: поставщик, модель, канал, поток,
результат. Account/request IDs не используются как metric labels.

Без дополнительной настройки **внешняя отправка выключена**, локальная таблица
диагностики работает из БД. Для собственного OTLP/HTTP collector разработчик задаёт
`SHLUZ_OTLP_ENDPOINT` — базовый URL; экспорт идёт на `/v1/metrics` и `/v1/traces`.
Метрики отправляются каждые 30 секунд. Никакой платный сервис не подключается.
Collector и его панель не разворачиваются автоматически. URL не должен содержать
логин, пароль, query или fragment. За пределами доверенной сети использовать HTTPS.

`SHLUZ_STREAM_TIMEOUT_SECONDS` — общий предел, по умолчанию 120 с;
`SHLUZ_STREAM_IDLE_TIMEOUT_SECONDS` — ожидание очередного фрагмента, по умолчанию 30 с.
Общий предел дополнительно ограничен сроком резерва минус 5 с и охватывает
заблокированную передачу клиенту. Тайм-аут Telegram также ограничивает свой HTTP-запрос.
Настройки меняет агент/разработчик, не владелец вручную.

## Миграция и исправление резервного копирования

Миграция `20261019_08` после `20261018_07` добавляет признаки и nullable-времена в
UsageEvent, не сбрасывая аккаунты, тарифы, демо и историю. История Telegram остаётся
своей SQLite. Схемы сайта и web-файлы не меняются.

В прежней версии проверка read-only WAL-базы без файла shared-memory могла пытаться
создать служебный файл в read-only томе. Это воспроизведено тестом с committed WAL.
Новый backup проверяет полную **временную writable-копию**, включая WAL; оригинал
остаётся read-only и попадает в архив с исходными метаданными. Не используется
`immutable=1`, не удаляется исходный WAL и не игнорируется проверка целостности.
Поток архива записывает хост, как раньше. Неудачная копия не запускает миграцию;
старые процессы запускаются снова. Причина из stderr классифицируется безопасно,
не раскрывая секретные пути/тексты.

Это исправление воспроизведённого дефекта, не утверждение о прочитанных логах
компьютера владельца: прежнее общее сообщение само по себе не доказывает причину.
Новая версия запускателя нужна и для обновления приложения, и для изменения backup.
Владельцу достаточно скачать новый архив и открыть Shluz.cmd. Удалять тома,
переустанавливать Python/Docker или копировать env-файлы не требуется.

## Проверки и внешние ограничения

Тестируются фрагментация SSE, соблюдение демо/прав, отказ провайдера, неизвестный
результат, privacy метрик, однократный учёт, реальный localhost HTTP и отключение
клиента; Telegram updates/provider HTTP синтетические. Docker CI проверяет
остановленную WAL-историю и восстановление архивов на изолированных данных.
Настоящие сообщения владельцу, платная генерация и Windows Docker Desktop владельца
не проверяются из этой среды. Результат CI конкретного коммита проверять отдельно.
