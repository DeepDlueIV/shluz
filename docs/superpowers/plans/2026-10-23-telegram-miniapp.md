# Telegram Mini App Implementation Plan

**Goal:** Убрать управление из переписки, сохранив существующий бот и данные.
**Architecture:** Опциональная панель в процессе бота; серверная проверка initData,
общий Store/Controller/GatewayClient. Шлюз отвечает за доступ и деньги.
**Tech Stack:** Python/FastAPI, aiogram, статические HTML/CSS/JS без нового сборщика.
**Spec:** docs/telegram-miniapp.md

## Global Constraints

Отдельная ветка; никаких main/preview/production и платежей. Нет новых секретов
в клиенте. Старый classic по умолчанию, никаких изменений app/ и web/ других агентов.

## Review Focus

- Подделка initData, повтор/устаревшие подтверждения и чужие dialog IDs.
- Архив/отзыв доступа после открытия панели, гонки с текущей генерацией.
- Потеря соединения после изменения: повтор не создаёт новый диалог.
- API отказал: интерфейс не показывает ложный успех и сохраняет введённое название.
- Обновление/откат без новой регистрации, потери аккаунта/кошелька/истории.

## Задачи

- [ ] Красные тесты подписи/сессии и опционального режима.
- [ ] miniapp/auth.py: ограниченная сессия и подлинность Telegram.
- [ ] miniapp/server.py: список, создание/выбор, настройки, подтверждение удаления,
  экспорт, модели/профиль/расход/тарифы; нулевые генерации из UI.
- [ ] controller/delivery/runtime: чистая переписка и opt-in запуск web-сервера.
- [ ] miniapp/static: мобильная панель, ошибки/подтверждения/возврат в чат.
- [ ] Контрактные и браузерные сценарии, старый Telegram/full regression.
- [ ] Документация включения/отката, точная граница живой проверки; отдельный PR.
