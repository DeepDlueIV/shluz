# Панель Shluz: исправления после локальной проверки

## Цель
Владелец без опыта разработки управляет сервисом в браузере: ошибки не выбрасывают из формы, интерфейс тёмный, удаление не разрушает финансовую историю, журналы доступны наглядно, проверка запроса не требует изучения Swagger.

## Решения
- Исправить серверную обработку ошибок форм тарифов: вернуть HTML, показать ошибку рядом с формой, сохранить введённые значения. Название разрешено на русском; код остаётся латинским, с явной подсказкой и проверкой в браузере.
- Тёмная тема для всех страниц панели и технической документации. Не менять настройки самого ChatGPT.
- Вместо необратимого удаления — архивирование. Для тарифов использовать существующий active=false, обозначить раздел как «Неактивные / архив». Тариф с действующими подписками нельзя архивировать без предварительного переназначения пользователей.
- Для пользователя архив означает status=archived и отзыв всех действующих личных токенов. Историю запросов и подписок не удалять. Восстановление аккаунта не восстанавливает отозванные ключи. Технические и административные аккаунты не архивировать.
- Журнал административных изменений хранить в отдельной таблице: кто, когда, что изменил, объект и безопасные детали. Запись успешного изменения и действие сохраняются в одной транзакции.
- Технический журнал запросов: время, сгенерированный сервером ID, шаблон маршрута, HTTP-статус и длительность. Без тела запросов, URL-параметров, заголовков авторизации, паролей и полных ключей. Docker Desktop показывает этот журнал во вкладке Logs.
- /admin/logs: просмотр журнала с пагинацией; ссылка на существующий журнал расходов.
- /admin/test: простая форма «личный токен, сообщение, отправить», вызывающая настоящий /v1/chat/completions с mock-chat. Токен не сохранять в браузерном хранилище, не передавать в URL и не показывать в журнале.
- Подтверждение оплаты и автоматическое назначение прав остаются отдельным этапом; ручная панель — инструмент владельца, а не обязательный пользовательский путь.

## Безопасность и границы
Не удалять реальные данные, не вызывать Venice, не применять изменения к удалённому Supabase во время локального тестирования. Новая миграция должна работать в SQLite и PostgreSQL; таблицу административного журнала закрыть для публичных Supabase-ролей. Не обещать неизменяемость журнала от администратора самой БД. Сохранить совместимость публичного API.

## Точка продолжения ручного теста
Остановились на создании тарифа: браузер показал JSON-ошибку при русском коде. Подтверждения успешного создания тарифа и запросов пока нет. После обновления: тариф test с лимитом 2 запроса → пользователь → назначить тариф → выдать личный токен → /admin/test → два успешных ответа, третий блокируется → /admin/usage.
