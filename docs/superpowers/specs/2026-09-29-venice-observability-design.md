# Venice и наблюдаемость провайдера

**Дата:** 2026-09-29  
**Статус:** согласовано для реализации

## Цель

Подключить Venice как первый реальный AI-провайдер и дать администратору понятную браузерную картину по состоянию подключения, балансу, лимитам, моделям, ценам и расходу.

## Границы этапа

Этот этап отвечает за уровень **провайдера**. Пользователи, тарифы, подписки и индивидуальные квоты будут добавлены после подключения PostgreSQL/Supabase. Интерфейс уже должен явно показывать, какие разделы работают, а какие ещё не подключены.

## Поток запроса

```text
Harness / сайт / Telegram
          ↓
        Shluz
          ↓
    Venice API
```

Ключ Venice хранится только в переменной окружения сервера. В ответах API, HTML, логах и GitHub он не отображается.

## Функции

1. Venice подключается отдельным адаптером, не меняющим публичный OpenAI-совместимый API Shluz.
2. `GET /v1/models` возвращает доступные Venice-модели и продолжает работать с MockProvider в режиме разработки.
3. `POST /v1/chat/completions` умеет отправлять непотоковый текстовый запрос в Venice и возвращать нормализованный ответ.
4. Адаптер извлекает идентификатор запроса, токены и фактическую стоимость из ответа Venice.
5. Админ-панель показывает:
   - подключён ли Venice;
   - можно ли расходовать баланс;
   - текущую валюту списания и остатки USD/DIEM;
   - срок действия ключа и тариф API, если Venice их возвращает;
   - лимиты запросов по моделям;
   - список моделей, их тип, приватность и цены;
   - агрегированный расход за 7 и 30 дней по моделям и API-ключам;
   - понятную ошибку без утечки секрета, если Venice недоступен.
6. Данные загружаются из официальных endpoint Venice: models, billing balance, billing usage analytics и API-key rate limits.
7. Beta-endpoint аналитики считается необязательным: его отказ не должен ломать чат или всю админ-панель.

## Надёжность

- Таймауты задаются конфигурацией.
- Ошибки 401, 402, 429 и 5xx нормализуются в безопасные сообщения.
- Автоматические повторы допускаются только для временных 5xx/сетевых ошибок и только для идемпотентных GET-запросов. Платные POST-запросы автоматически не повторяются.
- Все тесты используют подменённый HTTP-транспорт и не тратят кредиты Venice.

## Переносимость

Настройки передаются через `.env`/переменные окружения:

- `SHLUZ_ACTIVE_PROVIDER`;
- `SHLUZ_VENICE_API_KEY`;
- `SHLUZ_VENICE_BASE_URL`;
- `SHLUZ_VENICE_TIMEOUT_SECONDS`;
- `SHLUZ_VENICE_ANALYTICS_LOOKBACK`.

Приложение по-прежнему запускается локально и через Docker без изменения кода.

## Не входит в этап

- регистрация пользователей;
- пользовательские тарифы и баланс;
- платежи;
- Supabase/PostgreSQL;
- потоковая выдача;
- генерация изображений;
- хранение полной локальной истории запросов.

Потоковая выдача и изображения становятся следующим подэтапом после стабильного текстового подключения и административного контроля.
