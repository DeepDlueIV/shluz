# Эксплуатация Shluz простыми словами

Этот документ предназначен для владельца сервиса без глубоких знаний системного администрирования.

## Где находятся закрытые настройки

Закрытые значения передаются через локальный файл `.env` либо через раздел **Secrets** выбранного хостинга.

| Переменная | Для чего нужна |
|---|---|
| `SHLUZ_ENVIRONMENT` | Среда: `development`, `staging` или `production` |
| `SHLUZ_BOOTSTRAP_API_TOKEN` | Временный общий токен доступа к API Shluz |
| `SHLUZ_ADMIN_USERNAME` | Логин владельца для `/admin` |
| `SHLUZ_ADMIN_PASSWORD` | Пароль владельца для `/admin` |
| `SHLUZ_DATABASE_URL` | Закрытая строка подключения к SQLite или PostgreSQL/Supabase |
| `SHLUZ_ACTIVE_PROVIDER` | `mock` для бесплатного теста или `venice` для реальной модели |
| `SHLUZ_VENICE_API_KEY` | Секретный API-ключ Venice |
| `SHLUZ_VENICE_BASE_URL` | Адрес Venice API; обычно менять не нужно |
| `SHLUZ_VENICE_TIMEOUT_SECONDS` | Максимальное ожидание ответа Venice |
| `SHLUZ_VENICE_ANALYTICS_LOOKBACK` | Период аналитики Venice, например `7d` |

Полные значения паролей, токенов, ключей и строки базы не должны попадать в HTML, логи или GitHub.

## Быстрая проверка без расходов

Оставьте в `.env`:

```dotenv
SHLUZ_ACTIVE_PROVIDER=mock
SHLUZ_DATABASE_URL=sqlite+pysqlite:///./data/shluz.db
```

Запустите:

```bash
docker compose up --build
```

Откройте:

- <http://localhost:8000/admin> — главная сводка;
- <http://localhost:8000/admin/users> — пользователи;
- <http://localhost:8000/admin/plans> — тарифы;
- <http://localhost:8000/admin/usage> — расход;
- <http://localhost:8000/admin/providers/venice> — Venice;
- <http://localhost:8000/docs> — ручная проверка API;
- <http://localhost:8000/health> — состояние сервера.

Режим `mock` не обращается к внешним моделям и не расходует деньги.

## Как работает база данных

### Локальная проверка

По умолчанию используется SQLite. Docker хранит файл в отдельном постоянном томе `shluz_data`. Обычная команда остановки не удаляет данные:

```bash
docker compose down
```

Команда ниже удалит контейнеры **и локальную базу**:

```bash
docker compose down -v
```

Используйте её только когда данные действительно больше не нужны.

### PostgreSQL или Supabase

Для перехода на управляемую базу код менять не нужно. В Secrets сервера заменяется одна переменная:

```dotenv
SHLUZ_DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST:5432/postgres?sslmode=require
```

После перезапуска контейнер применит миграции автоматически.

Подключённый к ChatGPT проект Supabase не изменяется автоматически. Перед восстановлением приостановленного проекта и применением миграций требуется отдельное подтверждение владельца.

## Что видно в административной панели

### Пользователи

Раздел `/admin/users` показывает:

- внутренний ID;
- роль и статус;
- связанные способы входа;
- активный тариф;
- число токенов доступа;
- количество запросов, токены и себестоимость.

Секретные токены не показываются и не хранятся в открытом виде.

### Тарифы

Раздел `/admin/plans` показывает:

- название и код тарифа;
- активность;
- месячный лимит запросов;
- месячный лимит внутренних кредитов;
- число подписчиков.

Пока это режим просмотра. Безопасное визуальное редактирование будет отдельным этапом.

### Расход

Раздел `/admin/usage` показывает:

- общую себестоимость в USD и DIEM;
- входные и выходные токены;
- разбивку по пользователям, моделям и каналам;
- последние учтённые запросы.

Содержимое сообщений и ответы модели в журнале расхода не сохраняются.

## Подключение Venice

Без реального ключа Shluz не выполняет живые запросы Venice. Тесты используют искусственные ответы, а приложение остаётся на `mock`.

Для подключения:

1. Создайте отдельный тестовый ключ Venice с ограниченным балансом.
2. Не отправляйте ключ в чат и не добавляйте его в GitHub.
3. Сохраните в `.env` или Secrets:

```dotenv
SHLUZ_ACTIVE_PROVIDER=venice
SHLUZ_VENICE_API_KEY=ваш_ключ
```

4. Перезапустите:

```bash
docker compose up -d --build
```

5. Проверьте `/admin/providers/venice`.
6. Выполните один небольшой запрос через `/docs`.

Платный POST-запрос автоматически не повторяется, чтобы не создать двойное списание при неясном сетевом сбое.

## Типичные ошибки Venice

| Ситуация | Что проверить |
|---|---|
| Неверный или просроченный ключ | Значение и срок `SHLUZ_VENICE_API_KEY` |
| Недостаточный баланс | Баланс Venice и валюту списания |
| Превышен лимит | RPM/TPM на странице Venice |
| Временная недоступность | Статус Venice и журнал контейнера |
| Не загрузилась аналитика | Повторить позже; чат и баланс работают независимо |

## Резервные копии

Для локального SQLite резервируется Docker-том либо файл базы после остановки сервиса.

Для PostgreSQL/Supabase необходимо:

- включить ежедневные автоматические резервные копии;
- хранить хотя бы одну копию отдельно от основного сервера;
- периодически проверять восстановление на тестовой среде;
- определить срок хранения истории расхода.

## Перенос на другой сервер

1. Установить Docker и Docker Compose.
2. Скачать репозиторий или готовый образ.
3. Создать `.env` из `.env.example`.
4. Установить уникальные длинные токен и пароль.
5. Указать строку базы и ключ провайдера через Secrets.
6. Запустить `docker compose up -d --build`.
7. Проверить `/health`, `/admin` и `/docs`.
8. Настроить домен и HTTPS.
9. Ограничить административную панель на уровне сети, когда это возможно.

## Как проверить работу

`/health` должен вернуть примерно:

```json
{
  "status": "ok",
  "service": "shluz",
  "version": "0.1.0"
}
```

Журнал контейнера:

```bash
docker compose logs --tail=100 shluz
```

## Перед публичным запуском

Обязательны:

- HTTPS;
- персональная регистрация и вход;
- пользовательские токены, роли и права;
- фактическое применение тарифов и лимитов;
- блокировка перерасхода;
- аудит административных действий;
- защита от перебора паролей;
- мониторинг ошибок и доступности;
- юридическая проверка коммерческого использования поставщиков;
- политика хранения и удаления пользовательских данных.
