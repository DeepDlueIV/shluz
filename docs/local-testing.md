# Продолжение локальной проверки Shluz

## Где остановились

Docker уже запущен, вход в панель выполнен. При создании тарифа с русским кодом открылась JSON-ошибка. Успешные запросы к тестовой модели ещё не подтверждены.

Следующая контрольная точка: создать тариф → создать пользователя → назначить тариф → выдать личный токен → получить два ответа и отказ на третьем запросе.

## Получить обновления

Откройте новую вкладку PowerShell в папке `shluz` и выполните:

```powershell
git pull --ff-only
docker compose up -d --build
```

Если Git сообщает о конфликте с локальными изменениями, не используйте `reset --hard`: пришлите сообщение разработчику.

Не копируйте `.env.example` заново поверх `.env`: ваши пароль и настройки уже сохранены. Не используйте `docker compose down -v`: это удаляет локальные данные.

После запуска откройте http://localhost:8000/admin и нажмите Ctrl+F5, чтобы обновить стили.

## Тариф и пользователь

1. В разделе «Тарифы» создайте тариф: код `test`, название «Тестовый», лимит запросов в месяц `2`. Остальные лимиты оставьте пустыми или нулевыми, тариф — активным.
2. Если тариф `test` уже есть, используйте его, не создавайте дубль.
3. В разделе «Пользователи» создайте нового тестового пользователя, назначьте ему тариф и нажмите «Назначить».
4. В его карточке раскройте «Выдать доступ», назовите доступ «Локальная проверка», выберите Harness, нажмите «Создать токен».
5. Скопируйте длинную строку `shluz_…`. Это личный ключ доступа пользователя, а не пароль админки и не ключ Venice. Он показывается один раз. Не публикуйте его в чатах или GitHub.

## Простой тест — без технической документации

1. Откройте http://localhost:8000/admin/test либо нажмите «Проверка запроса» в панели.
2. Вставьте строку `shluz_…` в «Личный токен» целиком, без слова `Bearer`.
3. Оставьте сообщение «Привет» и нажмите «Отправить тестовый запрос».
4. Ожидаемый ответ: `Shluz mock reply: Привет`.
5. Нажмите ещё раз — второй ответ успешный. Третий запрос должен быть отклонён из-за лимита.
6. Откройте «Расходы» и «Пользователи», проверьте два успешных запроса и исчерпанный лимит.

Если этот пользователь уже делал запросы, они тоже учитываются. Для чистой проверки создайте нового тестового пользователя. Mock не вызывает Venice: стоимость и количество токенов равны нулю, проверяется лимит количества запросов.

## Что раньше означало «авторизоваться» в /docs

На http://localhost:8000/docs нажмите **Authorize**, найдите **HTTPBearer**, вставьте личный токен без `Bearer`, нажмите **Authorize**, затем **Close**. Не заполняйте HTTPBasic: это отдельный вход в административные страницы.

Раскройте `POST /v1/chat/completions`, нажмите **Try it out**, вставьте:

```json
{"model":"mock-chat","messages":[{"role":"user","content":"Привет"}]}
```

Нажмите **Execute**. Однако для текущей проверки проще использовать `/admin/test`.

## Архив вместо удаления

В карточке пользователя или тарифа есть «В архив», подтверждаемое галочкой. История не стирается.

Архив пользователя закрывает доступ, отзывает токены и останавливает локальные подписки. При восстановлении нужно снова назначить тариф и выдать новый токен. Это не отменяет банковский платёж: платёжная система пока не подключена.

Тариф с действующими подписками нельзя отправить в архив, пока пользователям не назначен другой тариф. Старые записи доступны во вкладках «Архив» и «Неактивные / архив».

## Где смотреть журналы

- **Журнал** (`/admin/logs`): действия владельца с датой, объектом и безопасными подробностями изменения. Появляются после установки обновления, задним числом не восстанавливаются.
- **Расходы** (`/admin/usage`): обращения к моделям, стоимость, токены, успешные и неуспешные события.
- **Docker Desktop → Containers → контейнер Shluz → Logs**: технические HTTP-события. Поля `time`, `request_id`, `route`, `status`, `duration_ms`, при внутренней ошибке `error_type`. Номер запроса также показывается на странице тестирования.

Пароли, заголовки авторизации, ключи и тексты сообщений в эти технические журналы не записываются. Логи Docker не являются бессрочным архивом: после пересоздания контейнера старый журнал может исчезнуть. Журнал владельца и расход сохраняются в базе. Перед рабочим запуском потребуется срок хранения, ротация и резервное копирование журналов.

## Автоматические права после покупки

Панель владельца — ручной контроль и помощь пользователю. Конечный сценарий продукта: регистрация → подтверждённая оплата → автоматическое назначение подписки и квот. Этот сценарий ещё не подключён, как и сама платёжная система. Пользователям не планируется выдавать доступ к админке.
