# Проверка закрытого Telegram-бота

## Автоматизировано

`pytest -q` запускает существующие тесты шлюза и новые проверки Telegram.
Тесты диспетчера подают настоящие aiogram Update и используют реальный FastAPI
шлюз с mock-провайдером через ASGI. Ответы Telegram имитируются RecordingSession:
никаких реальных сообщений людям и платных вызовов в этих тестах нет.

Проверяется: отдельный токен каждого пользователя; закрытый доступ и группы;
привязка identity и коллизии; лимиты/резервы; сохранение истории после перезапуска;
диалоги и доступ только владельцу; очистка с подтверждением; экспорт; смена модели
и стиля; UTF-16/эмодзи/HTML; длинный ответ целиком; отмена/занятость/ошибки;
повторный update без повторного запроса; потеря ответа без автоповтора;
сохранение результата перед доставкой; блокировка второго процесса;
heartbeat и shutdown; отсутствие секретов в логах; отдельные Compose env/тома.

CI дополнительно запускает миграции, сборку образа, реальный HTTP smoke шлюза,
проверку профиля/identity/chat через контейнерный клиент Telegram и offline-проверку
бота в собранном образе. Эти проверки не подтверждают живое соединение с Telegram.

## Ручная приёмка после настройки BotFather

1. Запустите Compose по `telegram_bot/README.md`. Неизвестному пользователю `/start`
   должен показывать закрытую бету и его ID, не создавать платный запрос.
2. Добавьте двух тестировщиков с разными аккаунтами и персональными токенами канала
   Telegram. `/start` открывает меню; при mock видна пометка тестовой модели.
3. Отправьте текст. Сначала появятся typing/ожидание, затем ответ и кнопки.
   `/plan` должен отражать запрос в шлюзе; просмотр меню сам по себе не расходует квоту.
4. Ответьте ещё раз, откройте `/new`, затем `/history` и вернитесь в старый диалог.
   У второго пользователя не должно быть текста первого.
5. Проверьте `/models`, все стили в `/settings`, `/export`, `/clear` (сначала отмените,
   затем подтвердите), `/delete`. Проверьте, что кнопки не ломаются после удаления.
6. Для длинного текста используйте автоматический тест `test_long_answer_is_exported_in_full_not_truncated`;
   с настоящей моделью попросите большой ответ: он делится на части или приходит файлом,
   а не заканчивается на первых 4000 символах.
7. При долгой модели нажмите `/cancel`, затем `/plan`. Должно быть объяснение,
   что ожидание прекращено, но расход мог произойти. Не проверяйте это на дорогом провайдере.
8. Уменьшите квоту тестового тарифа, исчерпайте её. Ошибка должна предлагать проверку
   лимитов. Затем отзовите токен или удалите пользователя из списка доступа:
   новые генерации должны быть запрещены.
9. Перезапустите только бота: `docker compose restart telegram_bot`.
   История/настройки остаются. Прерванные генерации не отправляются повторно.
10. Остановите тестовый шлюз, проверьте понятную ошибку, запустите его снова.
    Бот должен восстановить обычную работу без создания нового аккаунта.

## Граница результата

Выполненные локальные/CI тесты следует сверять с фактическими логами запуска.
Работа с реальным Telegram требует вашего BotFather-токена; качество, latency,
расход и ограничения настоящей модели требуют отдельного живого теста.
Отправка картинок/аудио, оплата, публичная регистрация, синхронизация истории
между клиентами и раздельный биллинг каналов не реализованы в этой версии.
