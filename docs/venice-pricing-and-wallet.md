# Venice: цены API и розничная наценка Shluz

Публичная документация проверена 20.10.2026. Это исследование, не запросы к ключу
владельца и не автоматическая активация цен. Платных вызовов в этой работе нет.

## Официальные источники

- https://docs.venice.ai/overview/pricing — прайс моделей. Для текста USD за 1 млн
  входных/выходных токенов, отдельные cache read/write и пороги длинного контекста.
  Для изображений/аудио/видео другие единицы и варианты; нельзя всё считать текстом.
- https://docs.venice.ai/api-reference/endpoint/models/list — GET /api/v1/models,
  type=all для категорий. model_spec.pricing содержит input/output.usd; у части
  изображений есть матрицы quality/resolutions. Это каталог, не фактический счёт.
- https://docs.venice.ai/api-reference/endpoint/chat/completions — ответ включает
  usage.prompt_tokens/completion_tokens и cost с разделением по валютам usd/diem.
  Поддержка/полнота финального cost при SSE проверяется живым ограниченным запросом;
  отсутствие данных нельзя превращать в ноль или выдумывать число из документации.
- https://docs.venice.ai/api-reference/endpoint/billing/usage — ВАЖНО: старый путь
  /api/v1/billing/usage помечен 410, sunset 2026-09-16. Документация указывает замену
  GET /api/v1/billing/usage-history. Не строить новую сверку на старом endpoint;
  текущие параметры и права новой версии отдельно подтвердить перед интеграцией.
- https://venice.ai/pricing — прямо указано 100 credits = 1 USD. 10 USD → 1000 credits
  соответствует опубликованной конвертации. DIEM — отдельный механизм, не смешивать.

## Пример из прайса, не жёстко зашитая цена

GLM 5.2 (zai-org-glm-5-2): input 1.40 USD/1M, output 4.40 USD/1M,
cache read 0.26 USD/1M на дату проверки. Цена может измениться, свежий прайс
не заменяет проверку итогового usage/cost и дополнительных расходов модели.

Для простого uncached text без других платных действий оценка:
(input_tokens × input_rate + billable_output_tokens × output_rate) / 1_000_000.
С учётом cache, reasoning, длинного контекста, поиска, файлов и других режимов
нужна соответствующая структура цены, а не механическое применение одной формулы.

## Принято для Shluz

Пополнение зачисляется полностью. Наценка включается в розничную стоимость запроса:
себестоимость 0.01 USD +20% = 0.012 USD списания. Это прозрачно описывается клиенту
как тариф сервиса; не говорить «без комиссии/по цене Venice», если цена отличается.
USD и credits ×100 — представления одного кошелька, не два счёта.

Прайс доступен достаточно подробно для калькулятора по моделям. Автоимпорт каталога,
сверка usage-history и коммерческие unit-price карточки этим изменением не сделаны:
сначала проверить выбранные модели и реальные валюты расхода после оплаты. Внешний
PAYG закрыт без явно подтверждённой верхней стоимости полного запроса и caps; это
защита от риска тарификации, а не отсутствие API-адаптера. Подробности: wallet-and-access.md.
