# Сайт NoClip: локальное подключение

Итоговый сайт: https://noclip-web.vercel.app. Публичный гостевой режим пока выключен.

## Что запускать на этом Windows

- `D:\NoClip\Shluz\Start-Website.cmd` — гостевой Gateway на 127.0.0.1:18001 и защищённый HTTPS ngrok для сайта.
- `D:\NoClip\Shluz\Stop-Website.cmd` — останавливает только эти два сервиса, в том числе без state.json.
- `D:\NoClip\Shluz\NoClip.cmd` — основной Gateway и Telegram Mini App. Её cloudflared не является туннелем сайта.

Сайт работает через серверный bridge Vercel → ngrok с Basic Auth → только POST /v1/web/session, POST /v1/web/chat/completions, GET /v1/web/me. Admin, внутренние API и остальные методы закрыты. Inspector отключён. Секреты находятся в config/site-bridge вне Git, права owner+SYSTEM.

## Что осталось перед публичным включением

Проверить исправленный Turnstile и потоковый ответ в защищённом preview того же Vercel-проекта; подтвердить адрес клиента через цепочку прокси и согласованную настоящую модель. Сейчас гостевой экземпляр использует mock: это проверяет транспорт, но не качество или доступность модели. Платный Venice для тестов не используется.

Только после проверки и согласования включить гостевой режим на **noclip-web.vercel.app**. Тестовый адрес нужен для приёмки и не заменяет основной сайт. Автоматического включения public flag, слияния серверных веток или создания нового Vercel-проекта лаунчер не выполняет.

Подробный локальный результат: WEBSITE-LOCAL-CHECK.md. Начинать продолжение со сверки этого отчёта, Docker и config/site-bridge/state.json с фактическим состоянием.
