# Сверка денег шлюза с официальными ценами Venice — 2026-10-30

Документ ночного прогона. Источники: `docs/pricing/venice-official-2026-10-30.md`
(каталог), `docs/venice-pricing-and-wallet.md`, `docs/wallet-and-access.md`, код
`app/billing/service.py`, `app/usage/service.py`, живая БД шлюза (read-only).

## Как шлюз считает деньги (по коду)

1. **Единицы**: целые 1e-8 USD (`billing.models.FixedUSD`), USD и credits (×100) —
   два отображения одного баланса. Квант `QUANTUM = 0.00000001`.
2. **Резерв ДО вызова** (billing.service.reserve, внутри product.locked_session):
   `ceil(max_cost_usd × (1 + markup%/100))` из `WalletModelBound` (id = `provider:model`),
   проверенной человеком (`reviewed=true`, срок 24ч), при превышении caps — отказ.
   `mock:mock-chat` — нулевая цена, без правила. Параллельные запросы не тратят
   остаток дважды (транзакция + hold).
3. **Списание ПОСЛЕ** (settle): `cost_usd × (1 + markup%)` из ответа провайдера
   (`cost.usd`), идемпотентно (`debit:<event_id>` + состояния hold).
   Превышение резерва → клиент платит не больше резерва, правило помечается
   `reviewed=false` (перепроверка человеком). DIEM ≠ 0 или cost_known=false →
   hold `uncertain`, списания нет — сверка вручную в админке, повтор не списывает дважды.
4. **Наценка** берётся из тарифа (`plan.pricing_markup_percent`), фиксируется в
   UsageEvent. В живой БД у тарифа unlim наценка = 0 → billed == себестоимости.
5. **Цены НЕ импортируются автоматически** из каталога: `max_cost_usd` — проверенная
   человеком верхняя граница ПОЛНОГО запроса (вход+выход+накладные). Официальная
   таблица — материал для этой проверки, не замена ей.

## Живая сверка формулы (30.10, реальные события БД)

Формула каталога: `cost = (prompt×input + completion×output) / 1e6` (+cache-скидки).

| Событие | in/out | Себестоимость Venice | По каталогу (без кэша) | Расхождение |
|---|---|---|---|---|
| aion-3-5-mini, 1 ход, без кэша | 1716/148 | 0.0017605 | **0.0017605** | **0.0000%** — точное совпадение |
| deepseek-v4-1-flash-1017 | 1833/124 | 0.00017454 | 0.00069870 | факт ниже |
| deepseek-uncensored (32k контекст) | 31918/555 | 0.00134020 | 0.01126554 | факт ниже |

**Вывод 1 (формула подтверждена)**: событие без попаданий в кэш совпадает с
каталог-формулой до последнего знака — интерпретация единиц (USD/1M) и
`usage.prompt_tokens/completion_tokens` верна.

**Вывод 2 (расхождения — кэш)**: у событий с повторным контекстом факт лежит между
«всё по cache_input» и «всё по input» — Venice применяет cache-скидку за кэшированный
префикс (`cache_input` ≈ 1/20 от `input` у этих моделей). Факт ВСЕГДА НИЖЕ каталога —
клиент не переплачивает.

**Вывод 3 (пробел данных)**: Venice в `usage` отдаёт сплит кэш-попаданий, но шлюз
сохраняет только суммарные prompt/completion. Точная построчная сверка из БД шлюза
невозможна без сохранения сплита. Рекомендация (предложение в proposals): расширить
UsageEvent полями `prompt_cache_hit_tokens` (+ опционально reasoning tokens) —
тогда сверка станет точной автоматической.

## Следствия для правил рецензирования WalletModelBound

- Верхнюю цену считать по БЕЗКЭШЕВЫМ ставкам (консервативно, кэш — подарок клиенту).
- Для reasoning-моделей закладывать накладные токены размышлений (проверено 30.10:
  deepseek с effort=high расходует бюджет до вызова инструмента).
- Скрипт `scripts/check_venice_pricing.py` (N14) сверяет `wallet_model_bounds` с
  официальным каталогом и печатает отчёт; записи БД не изменяет.
