# План: обновление одной кнопкой, демо и права моделей

Основание: прямое поручение владельца продолжить согласованный план. Выполняется
без промежуточной приёмки. Сайт разрабатывается параллельно: `web/` не менять.
База исходников: dc0dca68652cf36f3acf3f4a4f6ae6cd049adf2d.

1. Windows-запускатель на Python stdlib + CMD: постоянный preview-канал GitHub Releases,
   SHA256 манифеста/образа, автоматический поиск прежнего owner Docker-проекта,
   сохранение секретов вне обновлений, backup остановленных SQLite-томов до миграции,
   загрузка проверенного образа, совместный запуск gateway/bot и открытие панели.
   Образ доставляется архивом GitHub Release, а не GHCR, чтобы первый запуск не требовал
   авторизации в registry или ручной публикации прав доступа к пакету. Никакой сборки у владельца.
2. Демо: Start регистрирует сразу в режиме demo; закрытые приглашения остаются режимом.
   Разовый пакет 3 запроса на аккаунт, настройка администратором; повтор/месяц/канал не
   пополняют пакет. Использовать mock до явного выбора реальных моделей владельцем.
3. Права: пересечение тарифа и канала на сервере и в /models; короткие запросы демо,
   атомарное резервирование; одинаковые контракты для будущего web/desktop.
4. Понятные остатки/ошибки Telegram, тарифы и кнопка оплаты без процессинга.
5. Автотесты, CI, публикация preview; обновлённые документы и передача API агенту сайта.

Источник Venice Rust gateway: архитектурная справка, не повод переписать Shluz.
Применить принцип атомарного контроля квот в БД и общий серверный контроль клиентов.
Не копировать автоматические повторы POST, сырые ошибки upstream или второй gateway.
Streaming и OpenTelemetry Collector не добавлять в рамках этого задания.

Ограничения: не менять main, живой сервер, токены/балансы Venice или платежи.
Резервная копия не означает автоматический rollback после несовместимой миграции.
Локальный Docker Desktop владельца не доступен этой среде; Linux Docker и Windows
логика запуска проверяются в CI. Публикация кода не равна установке у владельца.
