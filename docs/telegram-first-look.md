# Первый просмотр Telegram-бота

Технические проверки выполняет разработчик в CI. От вас здесь нужны только личный
бот, ввод секретов на вашем компьютере и оценка удобства интерфейса.
Используется уже проверенный шлюз `compose.owner.yaml` на порту 18000 и бесплатный mock.

## 1. Создать бота

В Telegram откройте официальный **@BotFather**, отправьте `/newbot`, следуйте подсказкам.
Сохраните выданный токен бота у себя; не отправляйте его в чат или GitHub.

## 2. Два файла

В папке `shluz` скопируйте `.env.telegram.example` в `.env.telegram`.
Замените `CHANGE_ME_BOTFATHER_TOKEN` на токен BotFather. Другие значения пока не меняйте.
Создайте папку `secrets` и файл `secrets/telegram-access.json` с содержимым:

```json
{}
```

На Windows проверьте, что редактор не добавил расширение `.txt`. JSON сохраняйте как UTF-8.
Ваш прежний `.env.owner` не заменяйте: он относится к шлюзу, не к боту.

## 3. Запустить

При работающем Docker Desktop из папки `shluz`:

```sh
docker compose --env-file .env.owner -f compose.owner.yaml -f compose.owner.telegram.yaml up -d --build
```

Это подключает бота к тому же тестовому шлюзу и базе, не создаёт новый пустой шлюз
на другом порту. История бота находится в отдельном томе. Внешний порт боту не нужен.

## 4. Открыть доступ себе

Откройте созданного бота и нажмите **Start / Запустить**. Сообщение о закрытом доступе
покажет ваш числовой Telegram ID (не @username).

В прежней админке `http://127.0.0.1:18000/admin/users` создайте себе аккаунт,
назначьте тестовый тариф, например 20 запросов. В «Выдать доступ» выберите канал
**Telegram**, название ключа оставьте пустым. Скопируйте полный новый ключ `shluz_...`.
Не используйте отозванный ключ или исчерпанный тариф на 2 запроса.

В `secrets/telegram-access.json` вместо `{}` запишите:

```json
{
  "ВАШ_ЧИСЛОВОЙ_TELEGRAM_ID": "shluz_ПОЛНЫЙ_КЛЮЧ_ИЗ_АДМИНКИ"
}
```

Кавычки нужны. Это пример: замените значения своими. Токен BotFather сюда не вставлять:
он запускает бота; ключ Shluz даёт вашему аккаунту доступ к моделям.

После сохранения обновите только контейнер бота, чтобы учесть замену файла редактором:

```sh
docker compose --env-file .env.owner -f compose.owner.yaml -f compose.owner.telegram.yaml up -d --force-recreate --no-deps telegram_bot
```

## 5. Посмотреть

Повторите `/start`, отправьте «Привет». Оцените меню, диалоги, выбор модели,
настройки, ответы файлом и статус ожидания. Коды HTTP вручную проверять больше не нужно.
Ответ `Shluz mock reply: ...` — тест интеграции, а не качество настоящей нейросети.
Быстрый mock может ответить раньше смены анимации. `/last` возвращает сохранённый ответ
без новой генерации. «Другой вариант» — новый запрос, с новым расходом квоты.

Не запускайте два экземпляра с одним BotFather-токеном. Не используйте `down -v`:
это удаляет тома. При проблеме пришлите сообщение бота без секретов; полной ручной
приёмки заново не требуется. Этот локальный контур не предназначен для публичного SaaS.
