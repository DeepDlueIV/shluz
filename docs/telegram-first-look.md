# Первый просмотр Telegram-бота

Технические настройки, обновление и проверки выполняет Codex/разработчик.
Владельцу не требуется создавать файлы доступа и выпускать ключи на каждого человека.

## Если бот уже настроен

Попросите локального Codex обновить текущую feature-ветку и выполнить раздел
«Обновление уже настроенного бота» в [инструкции](telegram-auto-onboarding.md).
Ему нужно сохранить локальные секреты, данные и свои изменения. Токен BotFather,
который уже задан, используется повторно. Не создавайте нового бота.

Затем откройте своего бота и нажмите `/start`. Прежний действующий доступ переносится
автоматически. Если доступа ещё нет, бот создаст заявку — ничего копировать из Telegram не нужно.

## Как подключить нового человека

В админке откройте **Telegram** → выберите тариф → **Создать приглашение**.
Отправьте полученную ссылку человеку. После Start он подключится автоматически.

Человек, пришедший без приглашения, появится в **Telegram → Заявки и доступы**.
Нажмите **Разрешить доступ**. Пользователь нажмёт «Проверить доступ» или отправит сообщение.
Это управление закрытой бетой, а не ручная техническая настройка.

## Что посмотреть

Отправьте «Привет». Оцените меню, выбор модели, несколько диалогов, настройки,
историю, получение ответа файлом, `/last` и отмену ожидания.
`Shluz mock reply: ...` — бесплатный тестовый ответ, не качество настоящей модели.

Первоначальный BotFather-токен нужен один раз для самого бота. Его передают локальному
агенту/хостингу защищённым способом, не в GitHub и не в переписку.
Владелец не выполняет приёмочные команды API и не собирает технические логи вручную,
кроме действительно невоспроизводимой удалённо проблемы его окружения.
