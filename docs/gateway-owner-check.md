# Что владельцу проверить в Shluz

Цель — проверить доступ, тарифы, учёт и сохранность данных **без покупки токенов**.
Тест `mock` не доказывает качество нейросети или правильность цен будущего поставщика.
Все действия ниже выполняются на отдельном локальном экземпляре, не на рабочей базе.

## 1. Получить правильную версию

Код этой приёмки и доработанный бот находятся в ветке PR #10:
`implementation/telegram-beta-complete`. Пока PR не объединён, в `main` их нет.
В каталоге репозитория:

```sh
git status
git fetch origin
git switch implementation/telegram-beta-complete
git pull --ff-only origin implementation/telegram-beta-complete
```

Если локальной ветки ещё нет и `git switch` не создал её автоматически:
`git switch --track origin/implementation/telegram-beta-complete`.
Не используйте `reset --hard` и не удаляйте свои незакоммиченные изменения.
Можно вместо переключения распаковать исходники этой ветки в отдельный каталог.

## 2. Поднять отдельный шлюз

Нужны Python 3.12+ и Docker Engine/Desktop с Compose. Сценарий подготовки использует
только стандартную библиотеку Python. На Windows вместо `python` можно использовать `py`.

```sh
python scripts/gateway_owner_check.py --prepare
docker compose --env-file .env.owner -f compose.owner.yaml up -d --build
```

Подготовка создаёт `.env.owner` с новыми случайными секретами и провайдером `mock`.
Существующий файл не перезаписывает. **Не присылайте его в чат и не коммитьте.**
У Compose отдельное имя `shluz-owner-check`, том `owner_data` и локальный порт 18000.
Сервис не получает рабочий `.env` и не использует рабочий Docker-том. Telegram не запускается.

Откройте:

- `http://127.0.0.1:18000/health` — ожидается `{"status":"ok"}`;
- `http://127.0.0.1:18000/admin` — логин **owner**, пароль из `.env.owner`;
- `http://127.0.0.1:18000/docs` — ручные запросы API.

Всё привязано к loopback. Это проверка на вашем компьютере; не открывайте админку
в интернет ради теста. Если порт 18000 занят, остановите только свой старый тестовый
экземпляр или поменяйте локальную часть ports и передайте скрипту `--url` с новым портом.

## 3. Создать тестовый тариф и пользователей

В `/admin/plans` создайте тариф:

| Поле | Значение |
| --- | --- |
| Код тарифа | `owner_test` |
| Название | `Проверка — 2 запроса` |
| Запросов в месяц | **2** |
| Цена в месяц / наценка | `0` |
| Кредитов в месяц / лимит себестоимости | Пусто для первого теста |
| Резерв кредитов на запрос | `0` |
| Тариф активен | Да |

**Нулевой или пустой лимит здесь означает «без ограничения», а не запрет доступа.**

В `/admin/users` создайте `Тест A` и `Тест B`, назначьте этот тариф обоим.
Выпустите каждому собственный персональный API-токен. Для проверки Telegram выбирайте
канал **telegram**. Полный токен показывается один раз: сохраните его безопасно.
Создайте также `Без тарифа`, но не назначайте ему подписку.
Не используйте bootstrap/BotFather-токен как персональный ключ пользователя.

## 4. Проверить автоматически, затем исчерпать квоту

Скрипт попросит личный ключ скрытым вводом. Без флага генерации он только читает данные:

```sh
python scripts/gateway_owner_check.py
```

Все проверки должны показать `OK`: здоровье, защита админки, отклонение неверного ключа,
список моделей и личный профиль. На `/admin/usage` новых генераций быть не должно.

Затем **с ключом Тест A**:

```sh
python scripts/gateway_owner_check.py --send-mock
```

Ожидается точный mock-ответ и увеличение счётчика успешных запросов ровно на один.
Повторите команду ещё раз — второй запрос успешен. Третий запуск с тем же ключом
должен получить **HTTP 429**. В этом специально отрицательном тесте строка `FAIL`
и ненулевой код завершения скрипта ожидаемы: квота должна остановить генерацию.
С ключом `Тест B` запрос ещё должен проходить — чужая квота его не расходует.

Скрипт не повторяет генерацию при ошибках, не выбирает платную модель, не выводит ключ
или текст ответа. Один успешный запуск `--send-mock` расходует одну тестовую квоту.

## 5. Остальные обязательные проверки

Для ручного POST в `/docs` нажмите **Authorize**, вставьте только персональный ключ,
выберите `POST /v1/chat/completions`, **Try it out**, затем тело:

```json
{
  "model": "mock-chat",
  "messages": [{"role": "user", "content": "Проверка владельца"}],
  "stream": false
}
```

| Действие | Ожидаемый результат |
| --- | --- |
| Запрос без ключа / с испорченным ключом | 401. Модель не вызывается. |
| POST с личным ключом пользователя `Без тарифа` | 402, `subscription_required`. Просмотр `/v1/me` может быть доступен и показывать `plan:null`. |
| Отозвать токен тестового пользователя в админке; повторить POST | 401. Остальные действующие токены не отзываются автоматически. |
| Выпустить новый токен, затем заблокировать пользователя | 401 для его личных токенов. Проверять именно аккаунт, не удалять базу. |
| С действующим ключом указать `model: "nonexistent-owner-model"` | 404, `model_not_found`; квота успешных запросов не увеличивается. |
| Открыть `/v1/models`, `/v1/me` или страницы админки несколько раз | Никакого дополнительного расхода генераций. |
| Смотреть `/admin/usage` и пользователя | Правильные аккаунт, канал, модель, тариф и число успешных запросов. Нет чужого расхода. |
| Перезапустить тестовый контейнер | Пользователи, тарифы, токены и счётчик сохранились; исчерпанная квота не сбросилась. |

Команда перезапуска:

```sh
docker compose --env-file .env.owner -f compose.owner.yaml restart shluz
```

В mock нулевая себестоимость и нулевое количество модельных токенов — нормально.
Цена тарифа в админке пока справочная, не подтверждённый платёж.
Лимит запросов месячный по UTC, а не «два запроса после каждого перезапуска».

### Дополнительно: резерв кредитов

Создайте отдельный тариф/нового пользователя с **1 кредитом в месяц**,
**резервом 2 кредита на запрос**, запросами без лимита. POST должен быть отклонён
с 402 `credit_limit_exceeded` **до модели**. Не меняйте тариф действующих клиентов.
Это проверка предварительного ограничения; mock с нулевой ценой не проверяет
фактическую стоимость и маржу платной модели. Их проверяют после выбора провайдера
на малом бюджете и сверяют с его отчётом, отдельно от этого сценария.

## 6. Остановить тест без удаления данных

```sh
docker compose --env-file .env.owner -f compose.owner.yaml down
```

**Не добавляйте `-v`**, если хотите сохранить тестовую базу. Рабочий экземпляр шлюза
не останавливайте этими командами. Для обычного обновления данные удалять не требуется.

Если результат отличается, запишите действие, HTTP-код/`error.code`, время, аккаунт
и request ID, если показан. Не присылайте пароль, полный API-ключ, `.env` или переписки.

## Что этим не проверено

Живая модель, её цены/задержка, поведение при обрыве оплаченного запроса, реальная
одновременная нагрузка на production-базу, резервные копии с восстановлением,
внешний HTTPS и работа Telegram проверяются отдельно. До публичного запуска нужны
эти проверки; прохождение mock-сценария не равно готовности финансовой системы.
