# Отложенный план перед публичным запуском Shluz

Обновлено: 20.10.2026. Владелец просит сохранить эти задачи и пока не заниматься
внешними настройками. Это список незакрытых подключений, не отчёт об их готовности.

## Вернуться к этому перед открытием сайта

- [ ] **Почта для OTP.** Выбрать/подключить SMTP, настроить домен отправителя
  (SPF/DKIM/DMARC), сохранить секреты вне GitHub. Проверить доставку кода и ограничения
  отправки на согласованном адресе; парольная регистрация не нужна.
- [ ] **Turnstile.** Создать реальные sitekey/secret для нужных доменов, подключить
  серверную проверку и проверить её из целевого региона. Тестовые ключи не открывают
  публичное демо; при ошибке проверки платный запрос не отправляется.
- [ ] **Домен и HTTPS.** Подключить сайт и cookie API через совместимый origin/proxy,
  проверить Secure cookies, Origin/CSRF, доверенную IP-цепочку и запрет обхода origin.
  Настроить сетевые ограничения на размещении, не считать Python-лимитер защитой от всего DDoS.
- [ ] **Telegram Login сайта.** Настроить Client ID и Allowed URLs в BotFather для
  существующего бота. Подключить официальный вход к frontend и проверить, что тот же
  Telegram ведёт в аккаунт бота, а не создаёт новый бесплатный пакет.
- [ ] **Venice после оплаты.** Владелец сообщил об оплате. Проверить актуальный
  accessPermitted/остаток/срок ключа и один короткий запрос в согласованном лимите.
  Наличие оплаты не считается проверкой API. Реальных вызовов в CI нет; ключи и
  ответы не публикуются. Подготовлен `launcher/Check-Venice.cmd`, запуск не обязателен сейчас.
- [ ] **Модель и бюджет демо.** Согласовать модель, проверить цены и верхнюю стоимость
  полного запроса при заданных input/output/reasoning caps, задать бюджет в админке
  и ограничение у провайдера. Нулевой бюджет не означает безлимит; публичное платное
  демо до проверки не включать.
- [ ] **Живая приёмка и восстановление.** Проверить гость → один потоковый ответ →
  исчерпание квоты; email OTP/Telegram Login без повторной выдачи; ошибки, отмену,
  антибот и восстановление резервной копии. Изолированные тесты не заменяют эти
  проверки на настроенном домене и подключённых сервисах.

## Как продолжать работу

Агент при следующем обсуждении готовности сайта/публичного запуска читает этот файл,
кратко напоминает о незакрытых пунктах и выполняет технические действия сам. Владельцу
не поручать сравнение конфигураций, перенос файлов или ручную диагностику API.
Запрашивать только действительно недостающие доступы/решения, не публиковать секреты.

Общий контракт: [CLIENT_API.md](CLIENT_API.md). Настройка Telegram:
[telegram-web-login.md](telegram-web-login.md). Защита гостевого входа:
[web-access-and-abuse.md](web-access-and-abuse.md).

Новые обязанности не добавлять молча: платежный процессинг, перенос базы и связывание
существующих email/Telegram-кошельков отложены отдельно. Не объединять main и не
включать публичный доступ без отдельного разрешения. Успешная публикация preview не
означает установки на компьютере владельца или завершения этого списка.
