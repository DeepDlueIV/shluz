# Venice API: проверенная справка для Shluz

Проверено по официальным источникам 18.10.2026. Это карта интеграции, а не обещание
доступности всех функций для конкретного ключа. Секреты в этот файл не помещать.

## Подключение и права

Base URL: `https://api.venice.ai/api/v1`. Владелец указал модель `zai-org-glm-5-2`.
Ключ хранить только в локальном `.env` как `VENICE_API_KEY`. Шлюз поддерживает также
историческое имя `SHLUZ_VENICE_API_KEY`; при наличии обоих оно приоритетно. Не оставлять
в нём пустой placeholder одновременно с новым именем: использовать одно имя ключа.
Само наличие ключа НЕ переключает приложение с mock на Venice.

INFERENCE — тип разрешений, а не бесплатный тариф. Он допускает вызовы моделей;
ADMIN дополнительно допускает управление ключами и детальную финансовую аналитику.
План аккаунта, баланс, срок ключа, ограничения расходов и лимиты моделей — отдельные
свойства. Не определять их по префиксу ключа и не повышать ограничения автоматически.

`GET /api_keys/rate_limits` принимает оба типа ключей, не запускает генерацию и сообщает
`accessPermitted`, `apiTier`, `balances`, `keyExpiration`, `rateLimits`.
Значения берутся из фактического ответа; отсутствующие поля остаются неизвестными.
`GET /models` публичен: успешный каталог не доказывает правильность ключа.

## Карта endpoints → продукт

| Venice | Назначение в Shluz | Состояние |
|---|---|---|
| `GET /models?type=text` | Каталог моделей → меню Telegram через `GET /v1/models` | Адаптер уже есть; отдельные списки по тарифам/каналам ещё нужны |
| `POST /chat/completions` | Текст Telegram → `/v1/chat/completions` → Venice | Адаптер уже есть; сейчас обычный, не потоковый ответ |
| `GET /api_keys/rate_limits` | Лимиты/срок/доступность провайдера → панель владельца | Уже вызывается адаптером и новым probe |
| `GET /billing/balance`, `/billing/usage-analytics` | Подробная аналитика владельца, не баланс конечного пользователя | ADMIN; отказ INFERENCE не означает поломку генерации |
| `POST /audio/transcriptions` | Будущие голосовые сообщения → текст | В Venice описано, в Shluz не реализовано |
| `POST /audio/speech` | Будущая озвучка ответа | В Venice описано, в Shluz не реализовано |
| `POST /image/generations`, `/image/edit` | Будущие генерация/редактирование изображений | Не включать без отдельного задания и бюджета |
| `POST /augment/search`, `/augment/text-parser` | Будущий поиск/чтение документов | Не включать автоматически; отдельный расход |

Все пользовательские вызовы идут через шлюз. Ключ Venice не передаётся боту, сайту
или desktop-клиенту. Каталог поставщика не равен разрешённому списку тарифа.
Поддержку конкретной функции сверять с `model_spec.capabilities` из свежего каталога.

## GLM 5.2 и демо

На официальной карточке `zai-org-glm-5-2` указано, что модель НЕ uncensored.
Для проверки связи это подходящая выбранная владельцем модель, но не доказательство
отсутствия отказов и не выбранная демо-модель. Указанная цена: $1.40/1M входных и
$4.40/1M выходных токенов; это публичная цена, не подтверждение бесплатности ключа.
Модель для демо владелец выбирает позже. Не тестировать медиа/дорогие модели без согласия.

## Проверка ключа: выполняет разработчик/Codex

`scripts/venice_probe.py` читает секрет из env/локального `.env`, проверяет реальную
авторизацию перед каталогом. По умолчанию не делает генераций. `--chat` разрешает
ровно один короткий POST на выбранную модель с `max_completion_tokens=128`.
Не делает retries, не следует redirects, не печатает ключ, текст ответа или ID аккаунта.
Цена 128 токенов не является гарантией успешного ответа reasoning-модели: лимит может
уйти на reasoning. При пустом ответе не увеличивать бюджет и не повторять молча.

```sh
python scripts/venice_probe.py
python scripts/venice_probe.py --chat
```

Эти команды предназначены агенту, не владельцу. Не включать live-probe в обычный CI.
Владелец разрешил короткий тест предоставленного ключа, но не неограниченные расходы.
Секрет не копировать в GitHub workflow, комментарии, отчёт или архив.

Попытка из среды ChatGPT 18.10.2026: `ConnectError` ещё на GET rate_limits, HTTP-ответа
нет; DNS внешних доменов в среде не работает. POST НЕ отправлялся. Поэтому конкретный
лимит, остаток, срок ключа и реальный ответ GLM пока не подтверждены. Не выдавать этот
сбой среды за неверный ключ или отказ Venice. Локальную попытку выполняет Codex там,
где уже доступны сеть и секрет; сохраняет только обезличенный отчёт.

Перед включением Venice в пользовательский бот разработчик проверяет лимит выдачи
токенов, разрешённую модель, закрытые секреты и бюджет. `SHLUZ_ACTIVE_PROVIDER=venice`
меняет поставщика; в `.env.telegram` ключ Venice НЕ нужен. Приложение сейчас не
реализует конечную политику демо/списков моделей по каналам — не открывать весь каталог.
