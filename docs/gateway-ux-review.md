# Обновление панели владельца

## Что изменилось

Общая закреплённая шапка присутствует на всех страницах. В расходах — имена,
ссылки открывают нужного пользователя, в том числе архивного. Одинаковые имена
не объединяют расходы. Доступен поиск по имени/ID.

`0E-8` заменено на `0,00 USD`. Малые ненулевые суммы не округляются до нуля.
Точная сумма доступна при наведении; редактирование сохраняет точность полей.
Даты — в часовом поясе браузера, без JavaScript явно подписан UTC.
Расчёт месячных квот по-прежнему в UTC.

ID, роль, привязки, отозванные ключи и служебный аккаунт находятся в раскрываемых
блоках, а не удалены. Дополнительные настройки тарифа сворачиваются без сброса.
Расчётная выручка, маржа, кредиты и DIEM отделены от главных показателей расходов.
Токены модели подписаны «вход» и «выход», вместо непонятного «0 + 0».

Подсказки `?` объясняют резерв, бюджет, кредиты, наценку, ключи, каналы и другие
неочевидные термины. Открываются наведением, фокусом и нажатием; Escape закрывает.
Не обрезаются таблицей. Название ключа необязательно: канал и дата заполнятся сами.
Журнал действий показывает названия объектов и значения полей; сырой JSON скрыт.

## База данных

Созданный скриптом `.env.owner` и `compose.owner.yaml` по умолчанию используют SQLite
в отдельном Docker-томе `owner_data`, не Supabase. Личный файл на компьютере владельца
разработчик не читает; если он менял строку подключения, результат может отличаться.
Обзор теперь показывает тип базы по настройке работающего шлюза без URL и пароля.
В Supabase ничего не переносилось. Схема базы и логика биллинга здесь не менялись.

## Проверки вместо ручных команд владельца

Разработчик запускает полный pytest и lint. CI повторяет проверки на Python 3.12,
проверяет Docker/миграции и настоящий HTTP-сценарий: два успешных запроса, отказ
по квоте, независимость другого аккаунта, отсутствие тарифа, один и тот же ключ
до отзыва 200 и после 401, перезапуск процесса без потери данных.

Отдельный `pytest ui_tests -v` проверяет страницы в Chromium: шапку, переходы,
подсказки мышью/клавиатурой, мобильную ширину, поиск, скрытые значения формы,
выдачу ключа без названия и резервный вариант без JavaScript. Скриншоты CI содержат
вымышленные данные; полные ключи не фотографируются. Смотрите статус конкретного
коммита в checks PR, а не только наличие тестовых файлов.

Договорённость закреплена в AGENTS.md и PROJECT_CONTEXT.md: техническая приёмка
на разработчике. Владелец вводит свои секреты у себя и оценивает удобство.
Живой Telegram и платные модели без ключей не считаются проверенными.

## Как обновить вашу установленную версию

Перенесите обновлённый код в прежнюю папку `shluz`. Сохраните свои `.env.owner`,
`.env.telegram` (если уже создан), `secrets` и Docker-тома. Не создавайте пользователей
заново и не запускайте подготовку окружения повторно.

При работающем Docker Desktop из этой папки:

```sh
docker compose --env-file .env.owner -f compose.owner.yaml up -d --build
```

Это установка обновления, не повторение ручных тестов. Откройте прежний адрес
`http://127.0.0.1:18000/admin`. Если оформление осталось старым — Ctrl+F5.
Не выполняйте `down -v`, чтобы сохранить данные.

[Первый просмотр Telegram](telegram-first-look.md).

Источники: https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/ (паттерн в разработке,
это не сертификация WCAG); https://supabase.com/docs/guides/database/overview
