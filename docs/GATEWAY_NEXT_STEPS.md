Список ниже — план, не заявление о завершении. Main на паузе до решения владельца.

1. **Контролируемый живой Venice через шлюз → Telegram.** Серверный тестовый ключ,
   один разрешённый аккаунт/модель, малый расход и output cap. Проверить ответ,
   промежуточные фрагменты, отмену, корректный остаток/резерв и реальные usage/cost.
   Mock и оплата аккаунта сами по себе не подтверждают этот сценарий. Не публиковать
   ключи или тексты. Не открывать всем пользователям весь каталог.
2. **Закончить сверку денег.** Для выбранных моделей получить официальные цены,
   подтвердить единицы USD/credits/DIEM, отделить предварительный резерв от фактического
   списания. Отработать прерывание, неизвестный расход и повтор сверки без второго
   списания. Автоматизацию обновления прайса вводить с проверкой изменений, не заменяя
   утверждённую цену непроверенными данными.
3. **Согласовать клиентские ветки.** Desktop проверяет PR #11 `feat/opencode-tool-calling`
   с безопасным локальным инструментом; сайт читает docs/CLIENT_API.md и отложенный
   GO_LIVE_CHECKLIST. Не дублировать эту работу и не перезаписывать чужие ветки.
4. **Защита истории и эксплуатация — отложено владельцем 21.10.2026.** Пока не внедрять.
   Вернуться перед публичным запуском (GO_LIVE_CHECKLIST.md). Разработать шифрование базы/WAL/backup при
   хранении, отдельные ключи, их ротацию и восстановление; подтвердить доступы,
   восстановление после сбоя, срок удаления резервных копий и изоляцию пользователей.
   Это НЕ E2EE обычного Telegram-чата. Потеря ключей без резервирования может сделать
   историю невосстановимой. Уязвимый работающий сервис всё равно имеет доступ к тексту.
5. **Перед публичным доступом.** Небольшая нагрузочная проверка параллельных запросов,
   ограничения провайдера, уведомления об ошибках/росте расходов; OTP/Turnstile/HTTPS
   и реальные настройки BotFather по GO_LIVE_CHECKLIST. Новых платёжных интеграций
   или сквозной памяти между диалогами без отдельного решения не добавлять.
